<objective>
Produce the throwaway feasibility-spike tool: a single-project, single-file .NET 10 Windows console app that enumerates active display paths, detaches a user-chosen (DisplayPort, primary) monitor via CCD topology-path-removal, and confirms the detach through two independent enumeration APIs — then restores the original topology.

Purpose: This tool answers the ONE unvalidated core assumption of the whole project (Phase 1 goal): does true OS-level monitor disable actually work on the rig's AMD Radeon + DisplayPort hardware? The tool's design must be trustworthy enough that a FAIL result means "the driver doesn't honor it," not "the spike code had a marshalling bug."

Output: `spike/MonitorDetachSpike/MonitorDetachSpike.csproj` and `spike/MonitorDetachSpike/Program.cs`.

IMPORTANT — execution boundary: The executor of this plan runs in a Linux sandbox with no Windows/.NET runtime. Do NOT run `dotnet build`, `dotnet run`, or any Windows binary — there is nothing to execute against here. Every acceptance criterion below is a source-content assertion checkable by READING the produced files. The actual build/run and go/no-go decision happen later, when the USER runs this tool on their Windows rig and reports results back (that reporting-and-decision step is a follow-up interaction, NOT part of this plan).
</objective>

    Create `spike/MonitorDetachSpike/Program.cs` as a top-level-statements console program with `using WindowsDisplayAPI;`, `using WindowsDisplayAPI.DisplayConfig;`, and `using System.Windows.Forms;`. Dispatch on the first CLI argument into three modes; if no recognized mode is given, print a usage line listing all three and exit non-zero.

    Mode `--list`: call `PathInfo.GetActivePaths(virtualModeAware: false)`. Iterate the returned array with an integer index; for each path, iterate `path.TargetsInfo` and print a line containing the index, `targetInfo.DisplayTarget.FriendlyName` (print `(unavailable)` when null), `targetInfo.DisplayTarget.DevicePath`, `path.IsGDIPrimary`, and `targetInfo.OutputTechnology`. This is how the user identifies which index is the DisplayPort/primary monitor to disable (D-04/D-05).

    Mode `--disable <index>`: parse the second argument as an integer. VALIDATE it is within `[0, activePaths.Length)` after fetching `PathInfo.GetActivePaths(virtualModeAware: false)` into a local `originalActivePaths`; on a non-integer or out-of-range value, print a clear error whose message contains the literal text `valid range is 0..` (naming the actual upper bound, `originalActivePaths.Length - 1`) and `return`/exit non-zero — never index the array with an unvalidated value (Security Domain V5, Pitfall on out-of-bounds). Before mutating: capture `int screenCountBefore = Screen.AllScreens.Length`; capture the target's `DevicePath` (from the chosen path's first target) into a local for later comparison; and write a human-readable audit trail to `snapshot.json` next to the exe by serializing `originalActivePaths.Select(p => p.ToString()).ToArray()` with `System.Text.Json.JsonSerializer` (note in a comment that this JSON is an audit trail only — the real restore re-applies the in-memory array, never a JSON round-trip). Build `reducedPaths` = `originalActivePaths` with the chosen index excluded (`.Where((_, idx) => idx != targetIndex).ToArray()`). Call `PathInfo.ApplyPathInfos(reducedPaths, allowChanges: true, saveToDatabase: false, forceModeEnumeration: false)` — `allowChanges: true` is mandatory, not optional, so Windows can auto-promote a remaining display to primary when the removed path was the GDI primary (Pitfall B); do not pass `allowChanges: false`. Then VERIFY immediately via BOTH sources: re-query `PathInfo.GetActivePaths()` and check no active target's `DevicePath` equals the captured target `DevicePath` (`stillActive`); and read `int screenCountAfter = Screen.AllScreens.Length`. Print `PASS` only when `!stillActive && screenCountAfter < screenCountBefore`, otherwise print `FAIL` with which source still sees the monitor. Then sleep ~20 seconds (`System.Threading.Thread.Sleep(20000)`) and re-run the same two-source verification, printing a second PASS/FAIL — this catches DisplayPort hotplug re-detection that can silently re-add the display (Pitfall C); a single instantaneous check can give a false PASS. Finally, prompt the user to press Enter and RESTORE by calling `PathInfo.ApplyPathInfos(originalActivePaths, allowChanges: true)`, then print a final `Screen.AllScreens.Length` so the user can confirm the original count returned. Do NOT call, shell out to, or reference `pnputil`, `Get-PnpDevice`, `CM_Disable_DevNode`, or any elevated operation anywhere in this file — the admin fallback is a separate, manually-invoked path documented in plan 01-02's FALLBACK.md (D-08).

    Mode `--verify`: print the current active-path count from `PathInfo.GetActivePaths()` and the current `Screen.AllScreens.Length`, so the user can independently check display state at any time (including after manually trying the admin fallback in a separate elevated terminal).
  </action>
