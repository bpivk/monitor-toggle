<objective>
Close the single blocking verification gap from 03-VERIFICATION.md (same defect as 03-REVIEW.md CR-01): `WindowsAudioController.Restore` only falls back to friendly-name matching when the captured `DeviceId` is null/empty, never when the ID is present but stale (device unplugged/replaced since capture). A stale ID reaches `ApplyAndVerify`, which throws an uncaught `InvalidOperationException`. That exception is uncaught in `ToggleService.ToggleToNormalMode`, aborting restore of the other two audio roles AND skipping `MinimizeIfRunning` (APP-03) and `_snapshotStore.Clear()` — leaving the app permanently stuck reporting "Rig mode" with no automatic recovery.

Purpose: Make toggle-back restore reliable and self-recovering (AUDIO-02 "restore the exact previous default audio device... across all relevant audio roles", APP-03 reachability, and the project core value: "just as reliably restores everything to exactly how it was before").
Output: Stale-ID detection + per-role isolation in `Restore`; exception isolation in `ToggleToNormalMode`; a regression test proving minimize + clear survive a throwing restore.

Scope guard: This plan does NOT touch the forward-mode path. `SetDefault`/`SetDefaultForAllRoles`/`ToggleToRigMode` MUST keep their verify-and-throw-and-bubble behavior exactly as-is (D-03/D-04). The per-role try/catch goes in `Restore`'s loop and the isolation try/catch goes in `ToggleToNormalMode` — NOT inside the shared `ApplyAndVerify` (which would silently swallow forward-mode SetDefault failures too).
</objective>
