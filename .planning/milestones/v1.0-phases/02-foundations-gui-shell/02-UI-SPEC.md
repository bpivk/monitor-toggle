# Phase 2 — UI Design Contract

> Visual and interaction contract for Rig Toggle's Main window and Settings dialog. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** Rig Toggle is a WinForms (.NET 10) Windows desktop utility, not a web app. Web-native concepts in the template below (hex colors, CSS line-height, component registries) are translated to their WinForms equivalents throughout this document. Source: `CLAUDE.md`, `.planning/research/STACK.md`, `.planning/phases/02-foundations-gui-shell/02-CONTEXT.md` (decisions D-01 through D-15).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn/component-registry tooling does not apply to WinForms; not applicable (per D-01/D-02) |
| Preset | not applicable |
| Component library | `System.Windows.Forms` built-in controls only (Form, Label, Button, ComboBox, TextBox, GroupBox, OpenFileDialog, ErrorProvider). No third-party WinForms control library. |
| Icon library | none — no icons used in Phase 2. `ErrorProvider`'s built-in system warning glyph (native Windows shell icon) is the one exception; it ships with the framework, not a separate icon library. |
| Font | System default only: `Control.DefaultFont` (Segoe UI, 9pt at 96 DPI). Per D-02, no custom font is set anywhere; `AutoScaleMode: Font` (WinForms project default) handles DPI scaling automatically. |

## Spacing Scale

WinForms measures `Padding`/`Margin`/control size in pixels (logical pixels under `AutoScaleMode: Font`). The 8-point scale still applies directly to control spacing and form padding:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a field's ComboBox/TextBox and its inline warning label |
| sm | 8px | Gap between a label caption and its input control; gap between adjacent buttons in a button row |
| md | 16px | Default form padding (form edge to first/last control); vertical gap between GroupBox sections |
| lg | 24px | Gap between the Main window's mode indicator and the Toggle button |
| xl | 32px | Not used in Phase 2 (no layout region this large is needed on either window) |
| 2xl | 48px | Not used in Phase 2 |
| 3xl | 64px | Not used in Phase 2 |

Exceptions: Button minimum height is 32px (Settings Save/Discard) and 40px (Main window's Toggle button, primary action gets extra height for prominence — still an 8px multiple). No other exceptions.

## Typography

Per D-02 ("system-default styling — no custom colors/fonts/theming"), a **single system font is used uniformly across every role** — no per-role size or weight variation is introduced. WinForms has no CSS-style `line-height`; each control's height auto-sizes to the font's native metrics under `AutoScaleMode: Font`, so line-height is not separately configurable and is not specified here.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (Labels, ComboBox/TextBox text, button text) | 9pt (Segoe UI, system default) | Regular (400) | auto (system font metrics) |
| Label (field captions — "Monitor:", "Normal:", "Rig:") | 9pt (same as Body) | Regular (400) | auto |
| Heading (GroupBox section captions — "Monitor", "Audio Devices", "Application Path") | 9pt (same as Body) | Regular (400) — rendered by the native `GroupBox` caption chrome, not manually bolded | auto |
| Display | not used — no oversized/display-scale text exists in this phase's Main or Settings windows | — | — |

Do not override `Font` on any individual control. If a control needs visual emphasis (e.g. the mode indicator), achieve it through layout position and copy, not font-size/weight changes.

## Color

Per D-02, no custom colors are introduced anywhere. All surfaces use `SystemColors.*`, which automatically respects the user's active Windows theme (light/dark/high-contrast) with zero app-side logic.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `SystemColors.Control` | Form background on both Main window and Settings dialog |
| Secondary (30%) | `SystemColors.Window` | Input surfaces: `TextBox` background, `ComboBox` dropdown list background |
| Accent (10%) | `SystemColors.Highlight` (applied automatically by Windows, not set explicitly by app code) | Reserved for OS-native focus rectangle / selected-item highlight only — e.g. a focused `Button`'s default-button glow, a selected `ComboBox` item. Never manually assigned by app code. |
| Destructive | not used in Phase 2 | No destructive actions exist in this phase's scope (Save Settings/Discard Changes are non-destructive; the monitor-disable confirmation dialog is Phase 4's DISPLAY-03, out of scope here) |

Accent reserved for: the OS's own focus/selection rendering only (Tab-focus rectangle on buttons, selected item in the three device ComboBoxes). The app never sets a custom accent color on any control.

**Stale-device warning (D-10) — the one semantic exception:** use the native `ErrorProvider` component (a stock WinForms component, not a custom color) to show a system-standard warning glyph next to a picker whose saved selection was not found, plus a plain-`SystemColors.ControlText` inline label with the warning copy below the picker (see Copywriting Contract). This keeps the warning visually distinct without introducing any custom hex color, satisfying both D-02 and D-10.

## Registry Safety

Not applicable. WinForms has no npm-style component registry or shadcn-equivalent ecosystem — every visual control used in Phase 2 (`Form`, `Label`, `Button`, `ComboBox`, `TextBox`, `GroupBox`, `OpenFileDialog`, `ErrorProvider`) ships in the .NET 10 BCL itself. The two third-party NuGet packages used this phase (`WindowsDisplayAPI` for monitor enumeration, `NAudio` for audio endpoint enumeration, per `STACK.md`) are non-visual interop/enumeration libraries, already source-verified in `STACK.md`'s Sources section — they are not part of this design contract's registry-safety scope.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none — not applicable | not required |
| third-party | none — not applicable | not required |

## Window Layouts (WinForms specifics)

### Main Window

- `FormBorderStyle`: `FixedDialog`; `MaximizeBox = false`; `MinimizeBox = true`; not resizable (D-04)
- Recommended client size: **320 × 200px** (adjust ±8px per side only if system font metrics truncate text at the user's DPI setting)
- `StartPosition`: `CenterScreen`
- Vertical control stack, centered horizontally, 16px form padding on all sides:
  1. Mode indicator `Label` (top) — "Mode: Normal" / "Mode: Rig", updates on every toggle and on startup per D-14 (derived from snapshot-file presence)
  2. 24px gap
  3. Toggle `Button` — primary CTA, height 40px, width fills available layout width minus margins
  4. 8px gap
  5. Settings `Button` — "Settings…", height 32px
  6. 16px gap
  7. Companion-app status `Label` (bottom) — small, reflects real `Process.GetProcessesByName` detection (D-07/D-15)
- Since the form is fixed-size, runtime `Anchor`/`Dock` changes are not required for resize handling — controls are laid out once at design time to the sizes above.

### Settings Dialog

- `FormBorderStyle`: `FixedDialog`; `MaximizeBox = false`; `MinimizeBox = false`; `ShowInTaskbar = false`
- `StartPosition`: `CenterParent`
- Launched via `settingsForm.ShowDialog(this)` from Main's Settings button — modal, blocks Main until closed (D-03)
- Recommended client size: **420 × 380px**
- Three `GroupBox` sections stacked vertically (no tabs, per D-09), each with 16px vertical gap between them:
  1. **"Monitor"** — one `ComboBox` (`DropDownStyle = DropDownList`, real enumerated displays via `WindowsDisplayAPI.PathInfo.GetActivePaths()` per D-05) + inline warning row below (hidden unless stale, per D-10)
  2. **"Audio Devices"** — two labeled `ComboBox` rows, "Normal:" and "Rig:" (real enumerated endpoints via NAudio `MMDeviceEnumerator` per D-05), each with its own inline warning row
  3. **"Application Path"** — read-only `TextBox` showing the selected path + "Browse…" `Button` opening `OpenFileDialog` filtered to `*.exe` (D-06), with its own inline warning row
  - Each warning row = `ErrorProvider` glyph (anchored to the field) + plain-text `Label` below the field, shown only when D-10's stale-selection condition is true; hidden and collapsed (not just blank) otherwise
- Bottom button row, right-aligned: **Save Settings** (primary, `DialogResult.OK`) then 8px gap then **Discard Changes** (secondary, `DialogResult.Cancel`)
- Save Settings `Enabled = false` until monitor, both audio devices, and app path are all validly selected (D-12); re-evaluate on every relevant control's change event
- All three pickers re-enumerate on every `Form.Load` — no manual Refresh control exists (D-11)

## Interaction / DialogResult Flow

- **Open Settings:** Main's "Settings…" click → `new SettingsForm().ShowDialog(this)` → Main input blocked until the dialog closes (D-03)
- **Settings → Save Settings:** validate all 3 fields → persist via `SettingsStore` → `DialogResult.OK` → dialog closes → Main takes no further action immediately (per `ARCHITECTURE.md`: settings changes apply on the *next* toggle, never mid-flight)
- **Settings → Discard Changes / close box:** `DialogResult.Cancel` → dialog closes, in-memory edits discarded, nothing persisted
- **Main → Toggle click:** invokes `ToggleService.ToggleToRigMode()` / `ToggleToNormalMode()` synchronously against the real enumeration + fake mutation adapters (D-08, D-13); on success, updates the mode indicator (D-14, derived from snapshot-file presence) and the companion-app status line (D-15); on an unexpected exception from a fake adapter, show the basic failure message box defined in the Copywriting Contract above — full per-step partial-failure reporting (CORE-04) is explicitly out of scope for Phase 2 and belongs to Phase 5
- **Stale device on Settings reopen:** if a previously-saved monitor/audio device/app path is no longer found among the freshly re-enumerated options, the corresponding picker opens **unselected** with its inline warning shown (D-10) — never silently keeps a stale ID, never shows a greyed-out stale entry
