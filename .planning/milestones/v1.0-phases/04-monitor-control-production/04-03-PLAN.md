Replace the no-op `Disable`/`Restore` stubs in `WindowsMonitorController` with the real CCD-level mechanism validated by Plan 01's rig re-test. Disabling removes the configured primary monitor's path while repositioning every surviving path so one lands at `(0,0)` (RESEARCH Pattern 1 — the fix for the spike's `PathChangeException`). ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → OS Display Subsystem | The app requests a CCD topology change; the WDDM/GPU driver honors or rejects it. Single local user, no network. |
| state.json → Restore | Restore consumes previously-persisted topology data to drive a live mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | trusting `ApplyPathInfos`'s non-throwing return as proof of success | mitigate | Verify-and-throw against a fresh `GetActivePaths()` re-query after every mutation (D-03), mirroring Phase 3's `ApplyAndVerify`; `Screen.AllScreens` explicitly not used (D-04, spike Finding 2 staleness). |
| T-04-03-02 | Tampering | restoring with stale session-scoped LUIDs from old JSON | mitigate | Re-resolve `PathDisplaySource`/`PathDisplayTarget` live via `GetAllPaths()` matched on stable `DevicePath`; mode/signal reconstructed from stored primitives, never from an inactive path's default live data (Pitfall 2). |
| T-04-03-03 | Denial of Service | compounding a failed mutation with an automatic re-apply | mitigate | No rollback/retry on verification failure (D-05); the exception bubbles to MainForm's existing handler. Full per-step recovery is Phase 5 (CORE-04) scope. |
| T-04-03-04 | Input Validation | configured device path no longer active/detected | mitigate | Disable throws a clear "not currently active" error; Restore throws a clear "no longer detected" error naming the monitor — never indexes into an empty/mismatched array (RESEARCH Security Domain V5). |
| T-04-03-05 | Elevation of Privilege | display mutation requiring admin | accept | CCD `ApplyPathInfos` path is non-elevated (Phase 1 confirmed); no manifest/elevation change is introduced, preserving cross-process window focus (UIPI). |

Note: Local single-user desktop utility, no network-facing surface — auth/session/access-control ASVS categories are not applicable (RESEARCH Security Domain).
