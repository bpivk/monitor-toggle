<objective>
Build the two standalone, unwired building blocks of the monitor-tile dashboard: the ported GDI+ geometry helper and the `MonitorTile` presentational `UserControl`. Nothing on `MainForm` references them yet — Plan 02 hosts them.

Purpose: this codebase has zero existing `UserControl`s and zero owner-drawn controls in `RigToggle.App`. Isolating the new control in its own plan means its paint geometry, keyboard model, and theme contract are settled before the far riskier `MonitorPanelForm`-absorption refactor starts consuming them.
Output: `src/RigToggle.App/MonitorIconGeometry.cs` and `src/RigToggle.App/Controls/MonitorTile.cs`. The solution must still build and all existing tests must still pass — these files are purely additive.
</objective>

<hard_constraints>
Load-bearing rules. Violating any one fails the phase even if the control looks right.

1. `MonitorTile` NEVER references `IMonitorController`, `ToggleOrchestrator`, `ISettingsStore`, `MonitorConfirmDialog`, or `MonitorIdentifyOverlay`. It is presentational only and raises `ActionRequested`. `MainForm` performs every mutation (19-RESEARCH.md Pattern 1). A tile that mutates monitors is a second call site for the DISPLAY-12 zero-survivors guard, which is exactly what that decision exists to prevent.
2. NO hardcoded pixel literals inside `OnPaint`. Every coordinate, radius, stroke width, and font metric is derived from `ClientSize`, `Font`, or a named fractional constant (19-RESEARCH.md Pitfall 5 — `RigToggle.App.csproj` sets no `ApplicationHighDpiMode`, and `AutoScaleMode.Font` has zero visibility into custom paint code).
3. Do NOT add a `ProjectReference` from `RigToggle.App` to `RigToggle.IconGen`. `IconGen` is a dev-time-only console tool explicitly documented as "never referenced by RigToggle.App". The geometry constants are COPIED, and both copies carry a keep-in-sync doc comment (19-RESEARCH.md Pitfall 7).
4. Do NOT add any NuGet package, image asset, `.resx`, or `.Designer.cs` file. This phase installs zero external packages, and every glyph is procedurally drawn (D-01, 13-CONTEXT.md D-03).
5. `OnPaint` must never let an exception escape. A WinForms paint exception is process-fatal. Wrap the paint body in try/catch and `Trace.WriteLine` the failure, matching this codebase's swallow-with-trace convention.
6. ON/OFF status must be conveyed by TWO independent signals — fill-vs-outline shape AND color (D-02). Do not reduce this to a color swap or add a separate status dot.
</hard_constraints>
