  <what-built>
    `btnToggle` (a 288x40 stock `Button`) and `lblMode` (the "Mode: Rig/Normal/Unknown" label) are both deleted. In their place, `MainForm` now hosts a single owner-drawn `ToggleSwitch` row: a static "Rig Mode" label on the left, a compact 52x28 pill track with a 20px circular thumb on the right. Rig mode = thumb right, accent-filled track. Normal mode = thumb left, hollow gray-outlined track. Unknown mode (mode file missing/corrupted) = thumb dead-center, solid gray track. The tile strip moved up to sit flush with the window's top margin, since the space `lblMode` occupied was collapsed rather than left empty. Everything else — the tiles, Identify, the Settings gear, the tray menu, every confirmation dialog, and all monitor/audio/process logic — is unchanged.
  </what-built>
  <how-to-verify>
    Publish and run the app on the real rig. Work through every numbered check and report each as PASS or FAIL with a short note. Items 5-9 are the ones this build environment structurally cannot observe.

    1. **Success criterion 1 — it is a switch, not a button.** Open the window. The Rig/Normal action reads as a "Rig Mode" label with a small pill toggle at the right of the same row, sitting directly below the Identify button, with the Settings gear clearly separated further below. It must not look like a wide rectangular button.

    2. **Success criterion 2 — state is readable without color.** Toggle into Rig mode and back to Normal. In each state, take a screenshot and view it in grayscale (or just squint): the two states must still be distinguishable purely from the thumb being left-vs-right and the track being hollow-vs-filled. If the only difference you can see in grayscale is a shade, this fails.

    3. **Unknown state (DISPLAY-11 / D-07).** Close the app. Rename `%LocalAppData%\RigToggle\mode.json` to `mode.json.bak`. Relaunch. The switch must show the thumb dead-center on a solid gray track — visibly neither the left-hollow nor the right-accent state. Click it: it must refuse with "Rig Toggle's current mode is unknown — fix or delete the mode file, then restart the app, before toggling." and change nothing. Restore the file afterwards.

    4. **Success criterion 3a — keyboard.** With the mouse untouched, press Tab repeatedly: focus must reach the switch (a visible accent-colored ring hugging the pill, not a rectangle around the whole row), in the order tiles → Identify → toggle → Settings. Press Space: the mode must toggle exactly as a click does. Tab back and press Enter: same. Confirm the confirmation dialog appears on the keyboard path too when it would on the mouse path.

    5. **Success criterion 3b — live theme flip, normal start (Pitfall 1).** With the app running and its window open, flip Windows between Light and Dark in Settings > Personalization > Colors. The switch — label text, track outline, track fill, thumb outline, and its background — must recolor immediately alongside the tiles and buttons. If it freezes at the startup theme while its neighbours flip, this fails.

    6. **Success criterion 3b — live theme flip, `--tray` hidden start (Pitfall 1, second code path).** Exit the app. Relaunch it with `--tray` so no window is shown. Flip the Windows theme. Then open the window from the tray icon. The switch must already be correctly themed for the new theme. This is a separate code path (`InitializeTrayState()`) from item 5 and has to be checked independently.

    7. **Seam artifacts (Pitfall 2).** Screenshot the switch in the Off position (thumb resting near the track's left end) and again in the On position, then zoom in hard on the boundary where the thumb meets the track edge. Look for a doubled line, notch, or hairline gap along that boundary. A glance at normal viewing distance is exactly what missed this bug in Phase 13 — this needs a zoomed check.

    8. **Flicker and Mica blend (Pitfall 3).** Move the mouse slowly back and forth across the whole toggle row and press-and-hold on it. The hover and press fills must appear/disappear cleanly with no tearing or flashing, and the row's background must sit on the window's Mica surface the same way the tiles do — no opaque rectangle looking pasted on top of a different-toned background.

    9. **DPI (Pitfall 9).** Set Windows display scale to 125%, relaunch, and check: the pill's proportions still look right (thumb clearly circular and inset within the track, not clipped or swimming), the "Rig Mode" label is not clipped or overlapping the track, the focus ring is not cut off at the row's top/bottom edges, and the window's overall height still fits its content with no dead space or overlap. Repeat at 150%.

    10. **Gates and tray parity.** Confirm all of these still behave exactly as before this phase: (a) with no monitors configured in Settings, activating the switch toward Rig mode refuses with "Please choose at least one monitor to disable or enable in Settings before switching to Rig Mode."; (b) the DISPLAY-07 confirmation dialog still appears when `SkipMonitorConfirmation` is off, still names the monitors, and cancelling still changes nothing; (c) the tray context menu's first item text always matches the switch's current state ("Switch to Rig Mode" while the switch is off, "Switch to Normal Mode" while it is on), including right after a toggle from the tray; (d) toggling from the tray menu and from the global hotkey both still work and the switch's position updates to match.

    11. **Layout after `lblMode`'s removal.** Confirm there is no empty gap at the top of the window where the mode label used to be — the tile row should start flush against the top margin — and that the larger gap above the Settings gear (its de-emphasis cue from Phase 19) is still visibly larger than the gap above the toggle row.
  </how-to-verify>
