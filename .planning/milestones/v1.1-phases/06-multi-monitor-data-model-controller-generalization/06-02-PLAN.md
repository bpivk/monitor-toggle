<objective>
Generalize the `IMonitorController` contract from single-target (`Disable(string)`/`Restore`) to the N-monitor triad recommended by research (`GetAllMonitors`, `ActivateMonitors(IReadOnlySet<string>)`, `DeactivateMonitors(IReadOnlySet<string>)`, keeping `CaptureState`/`Restore`), and rewire `ToggleService` orchestration to drive both sets with the correct Extend-before-remove ordering (Pitfall 2), the D-07 `IsFullyConfigured` change, and the D-02 enable-set teardown. Update the test `FakeMonitorController` in lockstep and add tests so `RigToggle.Tests` stays green.

Purpose: This is the contract every later Phase 6 plan (Windows adapter, Settings grid, confirmation dialog) and every later v1.1 trigger phase builds against. Interface-first: define + orchestrate + test here so Plans 03/04/05 implement against a fixed, tested contract.
Output: Updated interface, `ToggleService`, `FakeMonitorController`, and `ToggleServiceTests`.

NOTE: After this plan, `RigToggle.Windows` and `RigToggle.App` will NOT compile until Plans 03/04/05 update `WindowsMonitorController`, `SettingsForm`, and `MainForm` to the new interface. That is expected and acceptable — those projects are `net10.0-windows` (not part of `dotnet test RigToggle.Tests`, not built on a non-Windows box). This plan's verification is `dotnet test RigToggle.Tests`, which references only `RigToggle.Core`.
