<objective>
Create the pure, Windows-free Core representation and formatting logic for a global hotkey, plus the persisted AppSettings fields, so every downstream App-layer surface (capture UI, registration, display) consumes one tested contract instead of re-deriving combo strings.

Purpose: The friendly-combo string format (D-01, modifier ordering + key-name mapping) and the modifier-vs-key distinction are pure logic with exact input→output — ideal TDD, and reusable by both the Settings capture textbox and any future display. Keeping it in RigToggle.Core (net10.0, zero Windows references) means it is unit-testable in RigToggle.Tests exactly like StartupArgs and ToggleResultFormatter already are.

Output: `HotkeyCombo` value type + modifier constants, `HotkeyFormatter.ToDisplayString`, two new nullable `AppSettings` fields, and unit tests (formatter behavior + settings round-trip).
</objective>
