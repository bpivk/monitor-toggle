<objective>
Build the cross-process single-instance guard end-to-end: a second Rig Toggle launch detects the already-running instance via a named kernel mutex, wakes that instance's window through a broadcast window message, and exits before constructing any UI — while the running instance restores and focuses itself using the exact tray-restore sequence it already ships.

This is the phase's tracer plan. Task 1 wires one thin path through all four layers (Core guard → Windows P/Invoke facade → App composition root → MainForm message receiver) and gets it compiling and committed. Task 2 closes PITFALLS.md Pitfall 8's receiver-ready race and the `Global\` namespace-privilege failure mode, test-first. Task 3 is the regression and prohibition audit.

**Decision coverage:**
- **D-01:** a blocked duplicate launch is silent — no toast, no dialog. The existing instance is restored with `Show()` / `WindowState = FormWindowState.Normal` / `Activate()`, the identical sequence `NotifyIcon_MouseClick` uses, reached through one shared private helper so the two paths cannot drift. Task 1 builds it; Task 3 gates the no-notification property with a negative grep.
- **D-02:** one universal duplicate-launch rule. Task 1 produces exactly one duplicate-launch branch in `Program.cs` with no sub-cases keyed on launch reason; Task 3 asserts the branch count.
- **Claude's Discretion — signal mechanism:** resolved in favour of `RegisterWindowMessage` + `PostMessage(HWND_BROADCAST, …)` over a named pipe. Three reasons, in order of weight: (1) STACK.md §2 recommends it explicitly and rules out IPC-with-payload as unneeded, whereas the named-pipe mention lives only in ARCHITECTURE.md's data-flow sketch, which CONTEXT.md itself flags as the inconsistent half; (2) `MainForm.WndProc` already special-cases one custom message, so this adds a second branch to an existing, rig-proven pattern instead of introducing a listener object, a background thread, and a stream lifetime to this codebase; (3) the signal genuinely carries zero payload, so a pipe's only distinguishing capability goes unused while its attack surface (a readable/writable named endpoint) does not.
- **Claude's Discretion — mutex naming and Pitfall 8 handling:** resolved to a fixed hardcoded GUID `8f3a1c42-7b5e-4d19-9a06-2e5c1f8b7d34`, and to handling the race on **both** sides as CONTEXT.md permits — the winner publishes a named readiness handle the instant it wins and signals it once its window handle provably exists, and the loser waits on that handle before broadcasting and broadcasts more than once.
- **Claude's Discretion — guard shape:** resolved to a new standalone `public sealed class SingleInstanceGuard : IDisposable` in `RigToggle.Core`, constructed only from the composition root, mirroring `ToggleOrchestrator`'s shape (small, single-purpose, doc-comment-heavy, scoped release) while sharing none of its mechanism per PITFALLS.md Pitfall 7.

Purpose: INSTANCE-01 and INSTANCE-02 — the user can never end up with two Rig Toggle processes, and a duplicate launch surfaces the instance they already have.
Output: two new source files, three modified source files, one new test class, and a green solution build.
</objective>
