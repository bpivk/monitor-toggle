<objective>
Prove the guard end-to-end by launching the real built `RigToggle.App.exe` as a child process: exactly one instance survives rapid relaunches, a blocked duplicate visibly restores the existing hidden window, and `--apply-update` runs unguarded while the guard is held.

This is the plan that turns plans 25-01 and 25-02 from "wired and compiling" into "observed working," and it is the only place in the phase where ROADMAP success criteria 1, 2 and 3 are actually satisfied rather than prepared for.

**Decision coverage:**
- **D-05:** both the rapid-relaunch test and the bypass-simulation test are automated xUnit tests launching the actual built exe as a real child process, not a manual script. Task 1 and Task 2 build them.
- **D-06:** they run in the normal CI build with no skip argument and no CI-exclusion trait. `.github/workflows/build.yml` already runs `dotnet test` solution-wide with no project filter, so it discovers this project unchanged — Task 3 confirms it rather than editing it.
- **Claude's Discretion — harness specifics:** resolved as follows. Target the `dotnet build` output (`src/RigToggle.App/bin/{Configuration}/net10.0-windows/win-x64/RigToggle.App.exe`), not the single-file publish output — CI builds but does not publish, and nothing in the guard's mechanism (a named kernel object, a registered window message, a window handle) behaves differently under single-file bundling. Ten iterations for the rapid-relaunch test plus a separate three-round tight-race test, because iteration count alone does not reproduce Pitfall 8's race — launching without waiting for readiness does. Flakiness is managed with generous bounded waits and real handle waits rather than sleeps, and any flakiness that survives is reported to the operator at the Task 3 checkpoint rather than papered over.

**Flagged deviation from D-05, requires operator awareness:** D-05's text names `RigToggle.Tests` as the home for these tests. Tests that launch a WinForms exe and read `MainWindowHandle` are unambiguously Windows-only; placing them in the cross-platform project would either break that invariant or require an operating-system guard that turns them into silent vacuous passes on Linux. The substance of D-05 (automated xUnit, real child process, not a manual script) is fully honoured; only the project name differs. Reversible in minutes if the operator prefers the literal reading.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-25-10 | Denial of Service | leaked child processes on the developer machine or CI runner | medium | mitigate | A test that starts a GUI process and fails before killing it leaves a live app holding the machine-wide name, which then makes every subsequent test in the run — and every real launch on that machine — believe an instance is running.
