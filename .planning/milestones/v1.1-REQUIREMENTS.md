# Requirements: Rig Toggle — v1.1 (Archived)

**Defined:** 2026-07-26
**Milestone Closed:** 2026-08-01
**Core Value:** A single reliable action that disables the primary monitor (not just powers it off) and switches audio output — so games that mishandle secondary-monitor launches reliably open on the rig monitor — and just as reliably restores everything to exactly how it was before.

## v1.1 Requirements — Final Outcomes

### Tray & Automation

- [x] **TRAY-01**: User can run the app tray-resident — closing the main window minimizes it to the tray instead of exiting. *Delivered Phase 8, revised into an independent Settings preference (default off) in Phase 11.*
- [x] **TRAY-02**: User can enable "start with Windows" via a Settings checkbox (off by default). *Delivered Phase 8.*
- [x] **TRAY-03**: User can right-click the tray icon for a context menu (Switch to Rig/Normal Mode, Settings, Exit). *Delivered Phase 8.*
- [x] **TRAY-04**: The tray icon visually reflects the current mode (normal vs. rig). *Delivered Phase 8.*
- [x] **TRAY-05**: Left-clicking the tray icon restores the main window. *Delivered Phase 8.*

### Trigger

- [x] **TRIG-01**: User can toggle via a configurable global hotkey; registration failures are surfaced, not silently swallowed. *Delivered Phase 9, rig-confirmed.*
- [ ] **TRIG-02**: User can toggle via a CLI argument (e.g. `--rig`/`--normal`) whether or not an instance of the app is already running. *Removed — Phase 10 was scoped but never planned/executed; see Outcome Notes below. Decided permanently out of scope, not a v2 candidate: tray + hotkey triggers already cover the daily-use need.*
- [ ] **TRIG-03**: User can query the current mode via a CLI argument (e.g. `--status`) without triggering a toggle. *Removed — same as TRIG-02.*

### Notification

- [x] **NOTIF-01**: User sees a toast/status notification confirming a toggle when it's triggered without the GUI open (hotkey/CLI/tray menu), showing what changed. *Delivered Phase 8.*

### Display

- [x] **DISPLAY-04**: User can configure a set of monitors to disable when entering rig mode (not limited to one). *Delivered Phase 6, rig-validated.*
- [x] **DISPLAY-05**: User can configure a set of monitors to enable when entering rig mode. *Delivered Phase 6, rig-validated.*
- [x] **DISPLAY-06**: Settings prevents saving a configuration that would disable every monitor. *Delivered Phase 6.*
- [x] **DISPLAY-07**: The pre-disable confirmation dialog names every monitor being disabled and enabled, not just one. *Delivered Phase 6.*
- [x] **DISPLAY-08**: A user upgrading from v1.0 keeps their previously-configured single monitor working automatically. *Delivered Phase 6, migration acceptance-tested against a genuine v1.0 settings.json.*

### Reliability

- [x] **CORE-06**: If a toggle is triggered while another toggle is already in progress, the app safely rejects the second request rather than risking corrupted state. *Delivered Phase 7, 4 deterministic reentrancy tests.*

### Diagnostics

## Outcome Notes

**TRIG-02 / TRIG-03 removed, not deferred.** The original v1.1 roadmap (`.planning/ROADMAP.md`, defined 2026-07-26) scoped Phases 6-10, with Phase 10 covering CLI Trigger + Single-Instance IPC. During execution, Phase 9's rig checkpoint surfaced a genuine, higher-priority user need (configurable tray close/minimize behavior), which was scoped and executed as Phase 11 instead of Phase 10. At milestone close (2026-08-01), Phase 10 was reviewed and explicitly dropped rather than completed. Initially logged as a v2-backlog candidate, but on reconsideration the user decided a CLI/IPC trigger isn't needed at all — Phase 8 (tray) and Phase 9 (global hotkey) already cover every trigger path this project needs. TRIG-02/TRIG-03 are permanently out of scope, not carried to v2.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Elevated/Task-Scheduler autostart | Would silently reintroduce the UIPI cross-process-focus problem the v1.0 H9 debug session already worked around; plain non-elevated Registry `Run` key is sufficient |
| Hotkey chord/sequence engine | Unused complexity for a single binding, single action |
| Full Windows App SDK / MSIX toast packaging | Conflicts with the standalone self-contained-.exe distribution constraint |
| Per-monitor sets keyed by index/position instead of stable `DevicePath` | Already burned once in v1.0 — must not be reintroduced at N-monitor scale |
| CLI trigger + single-instance IPC (TRIG-02, TRIG-03) | Scoped as Phase 10 for v1.1, never built. Tray (Phase 8) and global hotkey (Phase 9) already cover toggling without the GUI open; a CLI/IPC path for external tools (macro pads, Stream Deck) was judged not needed. Decided permanently out of scope at v1.1 close, 2026-08-01. |
| Toggle history/log (LOG-01) | Already deferred once in v1.0; still lower priority |
