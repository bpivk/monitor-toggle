# Phase 16 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Rig Toggle is a WinForms desktop app. There is no CSS/component-library design system. "Design contract" here means: exact control types, exact layout coordinates (WinForms Designer.cs is absolute-position, not flow-based), exact dialog copy/buttons/icon, and confirmation that new/modified controls participate in the existing Phase-12 `ThemeApplier`/`ThemeManager`-style theming rather than introducing unthemed controls. The Spacing/Typography/Color/Registry sections of the standard template are reinterpreted accordingly (see each section's note) — this phase does not invent new visual language, it extends two existing forms consistently (D-04/D-05).

## Color

Not applicable in the hex/60-30-10 sense — this is a native WinForms desktop app with a binary light/dark theme (Phase 12's `ThemeApplier`), not a web palette. The contract is: **every new control must be wired into the existing theme-follow mechanism identically to its Rig-mode counterpart, with zero new colors introduced.**

| Role | Value | Usage |
|------|-------|-------|
| Light mode grid background | `SystemColors.Window` | `dgvMonitorsNormal.BackgroundColor` — via `ThemeApplier.ThemeMonitorGrid` |
| Dark mode grid background | `Color.FromArgb(32, 32, 32)` | `dgvMonitorsNormal.BackgroundColor` — via `ThemeApplier.ThemeMonitorGrid` |
| Light mode grid cell fill | `SystemColors.Window` | `dgvMonitorsNormal.DefaultCellStyle.BackColor` |
| Dark mode grid cell fill | `Color.FromArgb(45, 45, 48)` | `dgvMonitorsNormal.DefaultCellStyle.BackColor` |
| Light mode grid header fill | `SystemColors.Control` | `dgvMonitorsNormal.ColumnHeadersDefaultCellStyle.BackColor` |
| Dark mode grid header fill | `Color.FromArgb(32, 32, 32)` | `dgvMonitorsNormal.ColumnHeadersDefaultCellStyle.BackColor` |
| Selection accent (both modes) | `SystemColors.Highlight` (light) / `Color.FromArgb(0, 90, 158)` (dark) | Grid cell selection only — via `ThemeApplier.ThemeMonitorGrid`, no new accent introduced |
| Labels/panel border | inherited (`BorderStyle.FixedSingle`, no explicit color override — same as `pnlMonitor`/`pnlAudioDevices`) | Panel chrome |
| `MessageBoxIcon.Warning` | OS-rendered stock icon | Both new startup dialogs (see Copywriting Contract) — not a custom color, system-themed automatically |

Accent reserved for: grid cell selection highlight only (identical to the existing Rig-mode grid — no new accent usage introduced by this phase).

**Interaction contract (mandatory, not optional):** `dgvMonitorsNormal` MUST be passed to `ThemeApplier.ThemeMonitorGrid(grid, IsDarkTheme)` at the exact same two call sites the Rig-mode grid already uses:
1. `SettingsForm_Load` (`SettingsForm.cs:182`, immediately after the existing `ThemeApplier.ThemeMonitorGrid(dgvMonitors, IsDarkTheme)` call)
2. `OnThemeChanged` (`SettingsForm.cs:144`, immediately after the existing call)

Omitting either call site produces an unthemed grid that silently reverts to light-mode colors under dark mode — the exact regression class `ThemeApplier`'s own doc comment (lines 6-22) exists to prevent. No other new-control theming work is needed this phase (the two new labels use default `Label` rendering, which `Application.SetColorMode` already handles correctly per `ThemeApplier.cs`'s own scoping comment — "every override here targets a specific control instance... never a blanket Controls-tree walk over base controls SetColorMode otherwise handles correctly").

### Settings — Normal-mode grid labels (D-05: mirrors Rig grid's convention exactly)

| Element | Copy |
|---------|------|
| Panel caption (`lblMonitorNormalCaption.Text`) | `Normal Mode` |
| Column header — disable | `Off (Normal)` |
| Column header — enable | `On (Normal)` |
| Explanation label (`lblMonitorNormalExplain.Text`) | `Only controls what changes when switching TO Normal Mode. A monitor not listed here is left untouched.` |

| Enable-column tooltip (`colEnableNormal.ToolTipText`) | `Turns this monitor on when switching to Normal Mode (for a monitor normally kept off, e.g. to save power).` |

**Tone check against Copywriting Contract's problem+next-step shape:** sentence 1 = problem statement (mode unknown, why); sentence 2 = explicit next step (verify manually before using Toggle). Matches the existing corrupted-snapshot precedent's shape (`ToggleService.cs:313-315`).

### Startup dialog 2 — Crash-recovery / toggle-in-progress marker found (D-02/D-03)

| MessageBox.Show parameter | Value |
|---|---|
| `owner` | `null` |
| `text` | `"Rig Toggle didn't finish its last toggle to {TargetMode} Mode cleanly — it may have crashed or been closed mid-toggle. No automatic retry has been attempted; please check your monitors and audio device manually before using Toggle again."` (`{TargetMode}` interpolates `"Rig"` or `"Normal"` from the cleared marker) |
| `caption` | `"Rig Toggle"` |
| `buttons` | `MessageBoxButtons.OK` |
| `icon` | `MessageBoxIcon.Warning` |

**Inform-only constraint (D-03):** exactly one button (`OK`) — no `Retry`/`Yes`/`No` option is ever presented here. This is a hard interaction constraint from D-03, not a copy preference.

**Dialog ordering (RESEARCH.md Pattern 3):** if BOTH conditions are true on the same startup (mode corrupted AND a crash marker exists), show the mode-corruption dialog FIRST, then the crash-recovery dialog SECOND — the mode-unknown condition is more severe and its "verify manually" instruction subsumes the crash dialog's own guidance, but the crash dialog still adds unique context (which mode the interrupted toggle was heading to) worth surfacing separately.
