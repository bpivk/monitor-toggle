<objective>
Build `MonitorPanelForm` — the live manual monitor panel (PANEL-01..05) — as a non-modal WinForms window backed directly by `IMonitorController`, satisfying DISPLAY-12 by reusing the existing zero-survivors guard rather than re-implementing it.

</objective>

<hard_constraints>
Load-bearing rules. Violating any one fails the phase even if the UI works.

1. Never re-implement the zero-survivors check. No pre-check that counts active monitors before calling `DeactivateMonitors`. The guard lives solely in `WindowsMonitorController.DeactivateMonitors` and is topology-aware (recomputes survivors from live CCD state at mutation time, unlike a UI-cached `IsActive` snapshot that can be stale by click time). DISPLAY-12 exists to prevent a second implementation of this rule.
2. Never route a panel action through `ToggleService`, `ToggleOrchestrator.ToggleToRigMode`, or `ToggleOrchestrator.ToggleToNormalMode`. Those are three-step sequences that would switch audio, launch/minimize the companion app, and write a `ToggleMode` the user never asked for. The panel's only `ToggleOrchestrator` usage is `BeginExclusiveMonitorAccess()`. `ToggleResult`, `ToggleStepResult`, `ToggleResultFormatter` must not appear.
3. Never write `AppSettings.MonitorsToDisable`, `MonitorsToEnable`, `NormalMonitorsToDisable`, `NormalMonitorsToEnable`, or `IModeStore`. The panel is ad-hoc and session-local (REQUIREMENTS.md Out of Scope). The single permitted settings write is `SkipMonitorConfirmation = true` from the confirm dialog's "don't ask again" checkbox.
4. Never use `System.Windows.Forms.Screen.*` — GDI `Screen.DeviceName` and CCD `DevicePath` are disjoint identity spaces (17-RESEARCH.md Pitfall 2).
5. No drag/arrange/resolution/orientation editing — strictly on/off.
</hard_constraints>
