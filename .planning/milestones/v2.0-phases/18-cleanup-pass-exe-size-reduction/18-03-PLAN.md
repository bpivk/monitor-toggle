<objective>
Shrink the self-contained single-file exe using four MSBuild-level levers only — `EnableCompressionInSingleFile`, `SatelliteResourceLanguages=en`, `InvariantGlobalization=true`, and the NAudio meta-package split — and prove the reduction with two real publish runs measured in bytes.

Purpose: the shipped exe is ~112 MB, dominated by the self-contained BCL/runtime bundle and unused localized/culture data. All four levers are packaging-only with zero application-code footprint, and none of them is IL trimming, which is permanently prohibited on this project because trimming's reachability analysis strips the COM-interop and P/Invoke paths this app is built on.
Output: three edited MSBuild files and a recorded before/after byte-count delta.
</objective>

</measured_baselines>

<hard_constraints>
**`PublishTrimmed` must remain literally `false`.** This is a locked project decision recorded in both CLAUDE.md and REQUIREMENTS.md's Out of Scope table. IL trimming's static reachability analysis misidentifies the `IPolicyConfig` COM-interop (audio default-device switching) and the `WindowsDisplayAPI` P/Invoke marshalling (CCD display topology) as unreachable and strips them, producing runtime failures on exactly the two code paths this app exists to perform. Do not set it to `true`. Do not delete the line. Do not add `PublishTrimmed` anywhere else. Do not add `PublishReadyToRun`, `PublishAot`, or any other lever beyond the four named in this plan, even if the size reduction looks tempting to extend.

**No elevation manifest.** Both touched `.csproj` files carry an explicit comment stating no elevation manifest element of any kind is present, keeping the tool `asInvoker`. Do not add `ApplicationManifest`, `<requestedExecutionLevel>`, or any related element while editing them.
</hard_constraints>

<package_legitimacy>
18-RESEARCH.md contains a `## Package Legitimacy Audit` section covering the one package change in this phase. `NAudio.Wasapi` 2.3.0 is dispositioned **Approved** — it is not a net-new third-party dependency but a narrowing swap within the already-vetted NAudio family: same publisher (`naudio` GitHub org), same monorepo, same `2.3.0` version already pinned in this solution. Verified directly against the NuGet flat-container registry API. `slopcheck` v0.6.1 does not support the NuGet ecosystem, so no automated scan verdict exists; the manual registry verification stands in its place. No `[ASSUMED]` or `[SUS]` package is involved, so no blocking human-verification checkpoint is required before this install. The swap also *reduces* shipped attack surface by dropping the unused `NAudio.WinMM`, `NAudio.Midi`, `NAudio.Asio`, `NAudio.WinForms` and `NAudio.Dmo` backends from the binary.
</package_legitimacy>
