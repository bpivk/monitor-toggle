    2. The source-collision rule that `AssignSource` implemented: an active target keeps its own `PathDisplaySource`; an inactive target must be given the first source not already claimed by another target in the same apply batch, otherwise two targets collide on one source and the apply silently mis-lands. Record that running out of free sources must throw rather than reuse.
    3. Source-ID renumbering across a mutation boundary: after `DeactivateMonitors` reduces the topology, the CCD driver commonly compacts the surviving monitor's native source index downward, freeing the disabled target's source. Any `PathInfo[]` array captured *before* that reduction therefore holds a stale `PathDisplaySource` assignment.
    4. `SetDisplayConfig` with `SDC_ALLOW_CHANGES` accepts a stale path array **without returning an error** while not necessarily keeping the mis-sourced target active. This is why replaying a cached pre-mutation `PathInfo[]` is unsafe in the general case and why the fast path was gated back to strict `SetEquals` (only the simple, no-enable-set-device case) rather than `IsSupersetOf`.
    5. Reconstruction rules that were rig-proven: re-resolve target identity live via `PathInfo.GetAllPaths()` matched on the stable stored `DevicePath` (never on a persisted, session-scoped LUID); take mode/signal values (position, resolution, pixel format, rotation, scaling, frequency, scan-line ordering) from the stored snapshot, never from an inactive live path's own `TargetsInfo` (Microsoft documents inactive-path mode/signal info as "set to default values"); never use the WinForms screen-enumeration API as the oracle (D-04); never attempt automatic rollback on verification failure (D-05).
