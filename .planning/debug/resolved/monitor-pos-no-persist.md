   - `[18:43:37.431] ... STARTUP pid=13292` — this process runs `DeactivateMonitors` on the DELL monitor at 18:43:38.833, exits cleanly (no shutdown line captured, but the app was evidently closed/restarted before the next block).

   - The gap between the two STARTUP lines (~23 minutes, and a changed PID) confirms the app process was restarted between the disable and the re-enable action.

## Resolution

root_cause: "WindowsMonitorController's mode/position cache (_lastKnownActiveModeByDevicePath) was declared as an in-memory-only Dictionary<string, PathInfo> with no on-disk backing, scoped to a single controller instance's process lifetime. This was a deliberate, evidence-based design decision at the time monitor-position-resets-to-de was resolved (no cross-process repro had been reported then), but the user's real workflow (closing and relaunching the app between disabling a monitor and re-enabling it) reaches exactly that gap: the re-enabling process's dictionary starts empty, so TryBuildScopedActivationPlan's cache lookup always misses for that device path and falls back to its blank-mode (driver-picks-the-position) branch, producing the reported 2-1-3 -> 1-2 collapse. Confirmed via direct source read (the field's own doc comment explicitly stated 'Does NOT survive an app restart') and the user's debug.log (two different pid= STARTUP lines bracketing the disable/enable pair for the same device path, with the enabling call's own log line reading 'no prior cache entry -- using greedy first-unclaimed selection')."

fix: "Added a small, additive on-disk JSON persistence layer following this codebase's existing JsonModeStore/JsonSettingsStore/JsonToggleInProgressStore convention exactly: a new CachedMonitorMode record (RigToggle.Core.Models), IMonitorModeCacheStore interface (RigToggle.Core.Abstractions), and JsonMonitorModeCacheStore implementation (RigToggle.Core.Persistence) persisting to %LocalAppData%\\RigToggle\\monitor-mode-cache.json (sibling of settings.json/mode.json/toggle-in-progress.json, wired in Program.cs's composition root). WindowsMonitorController's constructor now takes an IMonitorModeCacheStore, loads any persisted entries into _lastKnownActiveModeByDevicePath at startup (via a new pure seam, ToPathInfo), and CacheLiveModes now persists the current cache (via a new pure seam, ToCachedMonitorMode, and a bounded, recency-ordered cap of 32 entries so a permanently-unplugged monitor's entry does not accumulate on disk forever) on every call -- i.e. at both of its existing call sites (DeactivateMonitors' own capture, ActivateMonitors' swap-exclusion capture), unchanged. Persists the full PathDisplaySource identity (adapter LUID + source id) alongside Position/Resolution/PixelFormat, so SelectSourceForActivation's existing source-reclaim preference also survives a restart, not just position. The persistence save is wrapped in try/catch (IOException/UnauthorizedAccessException) so a disk failure can never abort an in-progress monitor toggle. Does not touch TryBuildScopedActivationPlan, PromoteToOriginIfNeeded, SelectSourceForActivation, the settle-poll-then-correct loop, or any other CCD-activation machinery -- only the cache's own lifetime changes."
