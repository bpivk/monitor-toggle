## Symptoms

expected: Clicking a single disabled monitor's tile on the MainForm dashboard enables only that one monitor. The other monitor(s) that were already disabled stay disabled.
actual: All three monitors turn on — the clicked one and both other monitors, including the one that should remain disabled.
errors: None reported — no exception dialog, no MessageBox, just the wrong end state.
timeline: |
  This exact bug (3 monitors, 1 enabled + 2 disabled, click one disabled tile) was previously investigated, root-caused, fixed, and confirmed fixed on the user's real 3-monitor rig on 2026-08-19 — see .planning/debug/resolved/monitor-enable-affects-other.md. Root cause there: WindowsMonitorController.ActivateMonitors calls WindowsDisplayAPI's PathInfo.ApplyTopology(Extend), a whole-topology CCD operation, to reactivate a single OS-disabled monitor; Extend has no per-target scoping and can reactivate OTHER currently-disabled-but-available monitors too. The fix added a post-Extend correction (ComputeUnexpectedlyActivated + a DeactivateMonitors call on the unexpectedly-activated set).

  Today (2026-08-20), while rig-verifying an unrelated Phase 25 (Single-Instance Guard) plan on the same physical rig, the user hit the identical symptom again via the identical repro path. Confirmed via git log that the fix commit (8dd83bc, "fix: ActivateMonitors no longer reactivates unrelated disabled monitors") is present on master and unmodified — `ComputeUnexpectedlyActivated` and its call site inside ActivateMonitors are intact, byte-identical to what shipped and was rig-confirmed. Phase 25's own commits never touched WindowsMonitorController.cs (confirmed via `git log --oneline -- src/RigToggle.Windows/WindowsMonitorController.cs`) or MainForm.cs's OnTileAction method (only WndProc/tray-restore code in MainForm.cs was touched). So this is not a case of the fix being reverted or overwritten by unrelated work — the exact same code that was rig-confirmed working nine days ago is now reproducing the bug it was supposed to have fixed.
reproduction: |
  1. On the 3-monitor rig, with one monitor enabled and two monitors disabled (via the tile dashboard).
  2. Click the tile for one of the two disabled monitors to re-enable it.
  3. Observe: the clicked monitor turns on AND the other still-should-be-disabled monitor also turns on — all three monitors end up active.
