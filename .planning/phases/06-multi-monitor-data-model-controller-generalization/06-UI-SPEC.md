# Phase 6 — UI Design Contract

> Visual and interaction contract for `SettingsForm`'s Monitor section (ComboBox → grid) and
> `MonitorConfirmDialog`'s multi-monitor message. WinForms desktop app, not web — this contract
> is expressed as exact control coordinates/sizes/behavior, not CSS tokens. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. See `06-CONTEXT.md` (D-03/D-04/D-06) and
> `06-RESEARCH.md` (Open Questions 2 & 3, Pitfall 5) for the decisions this contract implements.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — not applicable (WinForms desktop app, not a web/React project; no shadcn) |
| Preset | not applicable |
| Component library | WinForms built-in controls only: `GroupBox`, `DataGridView` (new this phase — first use in the codebase), `Label`, `Button`, `ComboBox`, `CheckBox`, `ErrorProvider` |
| Icon library | none — no icons used anywhere in the app (system-default convention, Phase 2 D-02) |
| Font | System default (`SystemFonts.DefaultFont`, resolves to Segoe UI 9pt on Windows 10/11) — `AutoScaleMode.Font` with base `SizeF(7F, 15F)`, matching every existing form. Do not set a custom `Font` on any new control. |

**Governing constraint (carried from Phase 2 D-02, unchanged by this phase):** system-default WinForms visual styling only — no custom colors, no custom fonts, no theming. The new grid must look like a stock `DataGridView`, not a styled/skinned one. This is why the Color and Typography sections below are declared "system default" rather than hex/px values — introducing a custom palette here would violate an existing, locked project decision.

## Spacing Scale

This is a WinForms pixel-coordinate layout, not a CSS spacing scale — the "tokens" below are the
actual coordinate deltas already established by the existing `SettingsForm`/`MonitorConfirmDialog`
Designer files, preserved and extended by this phase's changes (not invented fresh):

| Token | Value | Usage (existing convention, reused) |
|-------|-------|--------------------------------------|
| Form margin | 12px | Outer margin of every `GroupBox`/top-level control from the form edge |
| Section gap | 12px | Vertical gap between sibling `GroupBox` sections |
| Group inset | 22px | Y-offset from a `GroupBox`'s top edge to its first child control |
| Control-to-warning gap | 4-6px | Vertical gap between a picker control and its inline warning `Label` below it |
| Row height (grid) | 24px | `DataGridView` row height (default WinForms row height at 9pt Segoe UI — do not override) |
| Bottom margin | 8-12px | Gap between a `GroupBox`'s last child control and the group box's own bottom edge |

Exceptions: none — all new coordinates in this spec are derived by shifting existing controls down by a fixed delta (see Layout below), preserving every existing gap exactly.

## Grid Spec — `SettingsForm` Monitor Section (D-03/D-04)

### Control inventory (replaces `cboMonitor`)

| Control | Type | Name |
|---------|------|------|
| Grid | `DataGridView` | `dgvMonitors` |
| Column 1 | `DataGridViewTextBoxColumn`, `ReadOnly = true` | `colMonitorName` |
| Column 2 | `DataGridViewCheckBoxColumn` | `colDisable` |
| Column 3 | `DataGridViewCheckBoxColumn` | `colEnable` |
| Warning/error label (reused, generalized) | `Label`, `AutoSize = false` | `lblMonitorWarning` (existing control, message contract generalized — see Copywriting) |

### `DataGridView` configuration (exact)

- `AllowUserToAddRows = false`, `AllowUserToDeleteRows = false`, `AllowUserToResizeRows = false`, `AllowUserToResizeColumns = false`
- `RowHeadersVisible = false` — no row-header column; the Monitor-name column is the row identifier
- `SelectionMode = DataGridViewSelectionMode.CellSelect`, `MultiSelect = false`
- `ColumnHeadersHeightSizeMode = DisableResizing`
- `BorderStyle = System default (Fixed3D)` — do not override
- `EditMode = DataGridViewEditMode.EditOnEnter` (single click on a checkbox cell both selects and toggles — matches user mental model of a checkbox list)
- Column widths (grid content width 372px): `colMonitorName.AutoSizeMode = Fill` (resolves to 252px), `colDisable.Width = 60`, `colEnable.Width = 60`
- Column headers: `Monitor` / `Disable` / `Enable` (see Copywriting)
- One row per monitor returned by `IMonitorController.GetAllMonitors()` (the new enumeration method from `06-RESEARCH.md` Pattern 3 — **not** `GetActiveMonitors()`, which structurally cannot show OS-disabled-but-connected monitors that DISPLAY-05 requires selecting)
- Row label text: per the "Row label format" row in Copywriting Contract above

### D-04 mutual-exclusivity interaction (exact mechanism — RESEARCH.md Pitfall 5)

`DataGridViewCheckBoxColumn` cells do not commit their value until the cell loses focus, which would make a naive `CellValueChanged` handler fire one click late. Required wiring:

1. Handle `dgvMonitors.CurrentCellDirtyStateChanged`. Inside it, if the current cell is a checkbox cell, call `dgvMonitors.CommitEdit(DataGridViewDataErrorContexts.Commit)` immediately — this forces the value to commit on the same click.
2. Handle `dgvMonitors.CellValueChanged`. If the changed cell is in `colDisable` and its new value is `true`, set that row's `colEnable` cell value to `false` (and vice versa) — unhook/rehook the handler around this programmatic write, or guard with a reentrancy flag, to avoid infinite recursion.
3. After every `CellValueChanged`, call the generalized `ValidateSettingsForm()` (same call site pattern as today's `OnPickerChanged`).

Net effect for the user: clicking "Enable" on a row that already has "Disable" checked instantly unchecks "Disable" on that same click — never a two-click round trip, and never a state where both are checked simultaneously (D-04, locked).

### "Currently OS-disabled" row indication (RESEARCH.md Open Question 2 — resolved)

Plain text suffix only, per the Color contract's "no accent" constraint: `"LG UltraGear (currently OS-disabled)"`. No color, no icon, no bold. This directly answers "why would I check Enable for this row" without introducing any new visual language.

### Stale saved-monitor handling (RESEARCH.md Open Question 3 — resolved, generalizes D-10)

A saved device path that `GetAllMonitors()` no longer enumerates at all (physically disconnected/driver-removed — distinct from "currently OS-disabled but still connected," which *does* get a row) cannot have a grid row. Do **not** silently drop it from the persisted set on next Save (a temporarily-unplugged rig monitor must not lose its configuration). Behavior:

- On Save, the persisted `MonitorsToDisable`/`MonitorsToEnable` sets are computed as: `(previously-saved entries not currently enumerated by GetAllMonitors()) ∪ (currently-enumerated rows' checked device paths)`. Stale entries pass through untouched; only currently-visible rows are affected by grid interaction.
- `lblMonitorWarning` is generalized to accept a list and reused for this case, following D-06's own "always list every name, no truncation" convention (see Copywriting: "Stale saved-monitor warning" row).
- This warning is **informational, not blocking** — it must not disable `btnSaveSettings`. This is a deliberate behavior change from v1.0's single-`ComboBox` pattern (where an unselected/stale picker *did* block Save via `monitorOk`); blocking Save here would prevent the user from saving unrelated changes (e.g. a new audio device) while the rig monitor happens to be powered off. Document this divergence inline in code (matching the project's existing "explain *why*, not *what*" XML-doc convention).

### Empty state (grid has zero rows)

When `GetAllMonitors()` throws or returns zero monitors (matches the existing `cboMonitor` degrade-gracefully pattern):

- `dgvMonitors.Rows.Clear()`, `dgvMonitors.Enabled = false`
- `lblMonitorWarning.Text = "No displays detected."`, `Visible = true` (this is an informational/degrade state, not the red-icon `ErrorProvider` path — do not call `errMonitor.SetError` for this specific case, matching how `cboMonitor`'s existing empty-state string is *not* wrapped in a warning icon today)
- `btnSaveSettings.Enabled = false` (via the generalized `ValidateSettingsForm`'s "at least one monitor action configured" gate naturally evaluating to false)

### Validation contract (`ValidateSettingsForm`, generalized)

`btnSaveSettings.Enabled` is `true` iff **all** of the following hold (evaluated in this priority order for which single message `lblMonitorWarning`/`errMonitor` shows, since only one message is visible at a time):

1. **DISPLAY-06 gate (highest priority):** `WouldLeaveAtLeastOneMonitorActive(allMonitors, mergedDisableSet, mergedEnableSet)` is `true` (predicate from `06-RESEARCH.md` Code Examples). If false → show the "DISPLAY-06 blocking error" copy, disable Save.
2. **Non-empty gate:** `mergedDisableSet.Count > 0 || mergedEnableSet.Count > 0` (D-07's "at least one monitor-set action configured"). If false → show the "Empty-selection blocking error" copy, disable Save.
3. **Stale-device informational (lowest priority, non-blocking):** if 1 and 2 both pass but stale saved device paths exist, show the "Stale saved-monitor warning" copy — this does **not** disable Save.
4. If none of the above apply, hide `lblMonitorWarning` and clear `errMonitor` for the grid, exactly like today's `errMonitor.SetError(cboMonitor, string.Empty)` reset.
5. Existing gates unchanged: `audioNormalOk`, `audioRigOk`, `appPathOk` — all must also be true (unchanged from today's `ValidateSettingsForm`).

## Confirmation Dialog Spec — `MonitorConfirmDialog` (D-06)

### Message construction (exact, from `06-RESEARCH.md` Code Examples)

```csharp
private static string FormatNames(IReadOnlyList<string> names) =>
    string.Join(", ", names.Select(n => $"\"{n}\""));

var clauses = new List<string>();
if (disableNames.Count > 0) clauses.Add($"disable {FormatNames(disableNames)}");
if (enableNames.Count > 0) clauses.Add($"enable {FormatNames(enableNames)}");
lblMessage.Text = $"This will {string.Join(" and ", clauses)}. Continue?";
```

Both `disableNames` and `enableNames` must be resolved via `GetAllMonitors()` (not `GetActiveMonitors()`), since an enable-set monitor is inactive by definition at confirm-time and would otherwise fail to resolve a friendly name (RESEARCH.md Pattern 3's closing note).

### Exact layout coordinates (`MonitorConfirmDialog.Designer.cs`)

`lblMessage` grows by one line (72px vs. 48px) to comfortably fit the longer multi-name sentence on a personal rig's realistic 2-4 monitor count; every control below it shifts down by the same +24px delta, preserving all existing gaps exactly.

| Control | Location (x, y) | Size (w, h) | Delta from current |
|---------|------------------|-------------|---------------------|
| `lblMessage` | (12, 12) | (360, 72) | height 48 → 72 (+24) |
| `chkDontAskAgain` | (12, 88) | (200, 24) | y 64 → 88 (+24), size unchanged |
| `btnContinue` | (184, 124) | (90, 32) | y 100 → 124 (+24), size unchanged |
| `btnCancel` | (282, 124) | (90, 32) | y 100 → 124 (+24), size unchanged |
| `MonitorConfirmDialog.ClientSize` | — | (384, 168) | height 144 → 168 (+24) |
| `Text` (title bar) | — | `"Confirm Monitor Changes?"` | was `"Disable Monitor?"` — see Copywriting note on this default |

All other `MonitorConfirmDialog` properties (`FormBorderStyle = FixedDialog`, `AcceptButton`/`CancelButton` wiring, `StartPosition = CenterParent`) are unchanged.

### "Don't ask again" reset condition (interaction contract, not just data — affects when this dialog appears)

Per `06-RESEARCH.md` Pitfall 4: `SkipMonitorConfirmation` must reset to `false` whenever the *saved* `MonitorsToDisable` or `MonitorsToEnable` set changes, compared via `HashSet<string>.SetEquals` (order-independent) — not `List<string>` reference/`!=` comparison, which would either never reset (false negative on genuine changes) or reset too eagerly. This generalizes the existing single-string `monitorChanged` comparison in `BtnSaveSettings_Click` (line 311) to both sets.
