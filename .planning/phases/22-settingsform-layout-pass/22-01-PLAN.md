<objective>
Migrate SettingsForm's two monitor sections from hardcoded `Panel` + `Location`/`Size` positioning into a `TableLayoutPanel`-based, evenly-split two-column layout, and split today's shared `pnlAudioDevices` panel so each mode's audio picker moves into its own mode's column (D-01).

Purpose: This is the structural half of the phase — it is what turns the form from "all monitor stuff together, then all audio stuff together, in a 396px column inside an 828px window" into "Normal on the left, Rig on the right, each self-contained." Everything Plan 02 does below the columns depends on this scaffold existing.
Output: `src/RigToggle.App/SettingsForm.Designer.cs` with `tlpRoot`, `tlpModeColumns`, `tlpNormalColumn`, `tlpRigColumn`, `tlpAudioNormal`, `tlpAudioRig` in place, `pnlAudioDevices` and `lblAudioDevicesCaption` deleted, and a green build.
</objective>

<hard_constraints>
1. **Only `src/RigToggle.App/SettingsForm.Designer.cs` may change.** `SettingsForm.cs`, `ThemeApplier.cs`, and every other file stay byte-identical. This phase changes container type, `Dock`, `Anchor`, `Margin`, and `Padding` — never what a control does, binds to, or says (D-03's own framing).
2. **No control is deleted, renamed, or reworded.** The only two things removed are the `pnlAudioDevices` container itself and its `lblAudioDevicesCaption` label — its seven other children survive, relocated. Every other `Text`, `ToolTipText`, `HeaderText`, `Name`, event subscription, `ReadOnly`, `TabStop`, and `Cursor` value is preserved verbatim.
3. **Do not touch either grid's column configuration.** `colMonitorName`/`colMonitorNameNormal` keep `DataGridViewAutoSizeColumnMode.Fill`; `colDisable`/`colEnable`/`colDisableNormal`/`colEnableNormal` keep `Width = 66`. No `FillWeight` is introduced. (22-RESEARCH.md Pitfall 1 — the container is what changes, not the grid's own column math.)
4. **Never use `SizeType.Absolute`** for any row or column in any container added by this phase. `Percent` and `AutoSize` only (22-RESEARCH.md Anti-Patterns).
5. **No hand-rolled layout code.** No `Resize`/`Layout` event handler, no arithmetic that computes a width or height from another control's size. Every sizing need in this plan has a built-in `TableLayoutPanel` mechanism (22-RESEARCH.md "Don't Hand-Roll").
6. Follow the file's existing fully-qualified type style (`System.Windows.Forms.TableLayoutPanel`, `System.Drawing.Size`) — do not add `using` directives to a Designer file that has none.
7. The intermediate state after Task 1 (new columns rendered on top of the still-absolutely-positioned rest of the form) is **expected and acceptable**. Do not add temporary `Location` tweaks to make the half-migrated form look right — Plan 02 finishes it.
</hard_constraints>

**ErrorProvider icon clearance (new constraint this plan must honor).** `SettingsForm.cs` calls `SetError` on `dgvMonitors`, `dgvMonitorsNormal`, `cboAudioNormal`, `cboAudioRig`, `txtAppPath`, `txtHotkey`, and `chkStartWithWindows` (18 call sites). An `ErrorProvider` draws its 16px icon immediately to the right of the target control, inside the target's parent, and clips it if there is no room. Today the icon fits because every one of these controls is narrower than its panel. Under `Dock=Fill`/`Anchor=Left|Right` a control reaches its cell's right edge and the icon would be clipped — validation feedback would silently disappear. Every error-target control in this plan therefore gets a **right Margin of 20**.

**THEME-05 constraint (Phase 12).** Section containers are `Panel` with `BorderStyle.FixedSingle`, never `GroupBox` — `ThemeApplier`/`SetColorMode` cannot recolor a `GroupBox`'s 3D bevel. `pnlMonitorNormal` and `pnlMonitor` keep `BorderStyle = FixedSingle`.

**Theming is container-agnostic (verified, not assumed).** Every `ThemeApplier.*` call in `SettingsForm.cs` targets a named instance field (`ThemeApplier.ThemeMonitorGrid(dgvMonitors, ...)`, `ThemeApplier.ThemeComboBox(cboAudioNormal, ...)`), never a recursive `Controls` walk and never a container-type check. `grep -n "\.Parent" src/RigToggle.App/SettingsForm.cs` returns zero matches, and `pnlAudioDevices` appears only in `Designer.cs`. Reparenting requires **zero** code-behind changes.

**Column order changes today's left/right positions — intentional.** Today `pnlMonitor` ("Rig Mode") is the LEFT panel at x=12 and `pnlMonitorNormal` ("Normal Mode") is the RIGHT panel at x=420. This plan puts **Normal in column 0 (left)** and **Rig in column 1 (right)**, per the user's own framing in 22-CONTEXT.md ("One side is for normal mode and normal audio and the second for rig mode and audio") and 22-PATTERNS.md's explicit note. This swap is deliberate; do not "preserve" today's order.

**Label sizing rule.** `System.Windows.Forms.Label` defaults to `AutoSize = false`. The wrapping/fixed-height labels in this form (`lblMonitorExplain`, `lblMonitorNormalExplain`, and every `lbl*Warning`) rely on that plus an explicit `Size` for their height. Under a `TableLayoutPanel` `AutoSize` row, a label's preferred height is measured from its text and would collapse a multi-line label to one line. So: keep `AutoSize = false`, drop the `Location`/`Size` lines, set `Dock = Fill` (width comes from the cell) and `MinimumSize = new System.Drawing.Size(0, <today's height>)` (height floor preserved). Captions that are already `AutoSize = true` stay `AutoSize = true` with `Anchor = Left`.

**Grid height floor.** `dgvMonitors`/`dgvMonitorsNormal` are today fixed at 372x120. Under a `Percent` row inside an `AutoSize` chain, a `DataGridView`'s preferred height is derived from its populated rows — which are added at runtime in `SettingsForm_Load`, after `InitializeComponent()`. Give each grid `MinimumSize = new System.Drawing.Size(0, 120)` so today's grid height is a floor it can grow past but never fall below. This is a control-level `MinimumSize`, which is unrelated to (and explicitly permitted alongside) 22-RESEARCH.md Pitfall 2's prohibition on a **Form**-level `MinimumSize`.
