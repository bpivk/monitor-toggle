<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| managed C# → undocumented IPolicyConfig COM vtable | a wrong slot offset silently calls the wrong native method |
| IPolicyConfig HRESULT / OS audio state → app | an API may report success while the state did not change |
| persisted per-role deviceId → SetDefaultEndpoint | a stale/attacker-editable state.json id is passed to a system API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | IPolicyConfig vtable layout (wrong-slot bug) | mitigate | Task 1 reproduces the cross-verified 12-method layout with ResetDeviceFormat present; acceptance criteria assert the method count and ordering; Task 2/3 verify-and-throw would additionally surface a mis-dispatched call at runtime |
| T-03-05 | Repudiation / Spoofing | SetDefaultEndpoint reporting S_OK without changing state (Pitfall 6) | mitigate | Task 2/3 re-query the actual default via NAudio per role and throw InvalidOperationException on mismatch (D-03) — no silently-trusted HRESULT |
| T-03-06 | Denial of Service | COM object leak across repeated toggles (Pitfall 5/C) | mitigate | Every role cycle creates a fresh PolicyConfigClient and calls Marshal.ReleaseComObject in a finally — no cached RCW field |
| T-03-07 | Elevation of Privilege | IPolicyConfig runs in-process against a user-configured device id | accept | Single-user local tool, no elevation manifest (asInvoker per CLAUDE.md); the id addresses a local render endpoint only, no cross-user boundary crossed |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed (IPolicyConfig is hand-embedded source, not a NuGet reference, per CLAUDE.md/RESEARCH Package Legitimacy Audit: N/A) |
</threat_model>
