## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process args → Main | `args` (from the Run-key command string or any launcher) selects hidden vs. visible startup via StartupArgs (validated in 08-01). |
| SettingsForm → HKCU registry | The checkbox Save path calls Enable()/Disable(), the only user-facing action that mutates the Run hive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-EOP | Elevation of Privilege | Autostart write | mitigate | Enable()/Disable() target HKCU only (enforced in 08-01's adapter); Settings never touches Registry directly, only the injected interface — no elevation path introduced. |
| T-08-LIE | Integrity (false UI state) | Checkbox Save path | mitigate | On a registry-write exception the checkbox reverts to `IsEnabled()` and shows an inline warning, so the UI cannot report an autostart state that was not actually written. |
| T-08-DOS | Denial of Service | Hidden-start branch | mitigate | Startup selection uses the null-safe StartupArgs predicate; a malformed `args` falls through to normal visible startup rather than crashing (especially important for an autostart entry that would otherwise fail every login). |
| T-08-ORPHAN | Discoverability | ApplicationContext hidden start + Exit | accept (verify on rig) | Assumption A2: `Application.Exit()` terminates a never-shown ApplicationContext-hosted form per docs; flagged as an explicit rig-test scenario in 08-04 rather than asserted here. |
| T-08-SC | Tampering | npm/pip/cargo installs | n/a | No external packages added (Package Legitimacy Audit: not applicable). |
</threat_model>
