<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Rig-validate all Phase 8 tray / autostart / toast / hidden-start behaviors</name>
  <what-built>
    Tray residency (hide-to-tray on close, left-click restore), a right-click tray context menu (Switch mode / Settings / Exit) with a mode-reflecting icon + tooltip, a per-step toast on tray-menu toggles, an off-by-default "Start with Windows" Settings checkbox writing HKCU\...\Run, and a --tray hidden-startup path.
  </what-built>
  <how-to-verify>
    Run the published `RigToggle.exe` on the rig and confirm each:

    TRAY-01 (hide-to-tray): Click the window's X (and separately Alt+F4). Expected: the window disappears but the app keeps running (tray icon still present); it does NOT exit.

    TRAY-05 (restore): Left-click the tray icon. Expected: the main window restores and gets focus. Left-click again / double-click — expected: still fine (harmless re-restore).

    TRAY-03 (context menu): Right-click the tray icon. Expected menu order: "Switch to Rig Mode" (or "Switch to Normal Mode" per current mode) → "Settings" → separator → "Exit". Right-clicking must NOT restore the window (only left-click does).

    TRAY-04 (mode icon + tooltip): Toggle to Rig mode, then Normal. Expected: the tray icon glyph changes shape (not just color) and the hover tooltip reads "Rig Toggle — Rig Mode" / "Rig Toggle — Normal Mode" accordingly. At a fresh start, the icon already matches the current mode (no default/blank first-paint).

    NOTIF-01 (toast): With the window hidden to tray, use the tray "Switch to..." item. Expected: a balloon toast titled "Switched to Rig/Normal Mode" whose body lists Monitor/Audio/App outcomes matching what the GUI MessageBox shows. Force a partial failure if practical (e.g. an invalid companion path) and confirm the toast shows "FAILED (...)" with a Warning icon and is not cut off mid-word.

    TRAY-02 (autostart): Open Settings — "Start with Windows" is UNCHECKED by default. Check it, Save. Verify in `regedit` under HKCU\Software\Microsoft\Windows\CurrentVersion\Run a "RigToggle" value = `"<full exe path>" --tray`. Uncheck, Save — value is gone. (Optional but recommended: reboot / log off+on and confirm the app auto-starts hidden to the tray with no window flash.)

    D-06 hidden start: Run `RigToggle.exe --tray` from a terminal. Expected: NO window appears, tray icon present and mode-correct.

    Assumption A2 (flagged): While started via `--tray` and having NEVER shown the window, right-click tray → Exit. Expected: the process fully terminates (check Task Manager — no orphaned RigToggle process) and NO ghost tray icon remains (it should vanish immediately, not linger until hover).

    Ghost-icon check: From a normal (shown) start, use tray Exit. Expected: icon disappears immediately, process ends.
  </how-to-verify>
  <resume-signal>Reply "approved" if all pass, or list the specific scenario(s) that failed with what you observed.</resume-signal>
</task>
