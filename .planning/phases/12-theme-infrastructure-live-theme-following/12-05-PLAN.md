## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS event thread → form UI thread | `ThemeChanged` may arrive off the UI thread while a form is open |
| Long-lived provider → transient dialogs | App-lifetime `WindowsThemeProvider` outlives fresh-per-open `SettingsForm`/`MonitorConfirmDialog` |
| Managed → native (dwmapi.dll) | Immersive-dark-mode + Mica attributes on a possibly-unsupported OS (Windows 10) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02 | Denial of Service | ThemeApplier.ThemeButton/ThemeComboBox + each form's OnThemeChanged | mitigate | New helpers wrapped in try/catch (cosmetic-only, leave control unchanged on failure); all new calls sit inside the existing marshaled try/catch OnThemeChanged bodies — a theming failure cannot crash toggle/save/confirm flows. |
| T-12-03 | Tampering | DwmTitleBar immersive-dark-mode call | mitigate | Best-effort non-throwing HRESULT (D-07); applied only with a real Handle already in scope; silent no-op on Windows 10 / unsupported builds — same posture as the existing corner/backdrop calls. |
| T-12-05 | Denial of Service | SettingsForm / MonitorConfirmDialog ThemeChanged subscription lifecycle | mitigate | WR-01: add `Dispose(bool)` unsubscribe backstop to both transient dialogs (mirrors MainForm) so an abnormal dispose path that never fires FormClosed cannot leak a closed dialog onto the app-lifetime provider. |
| T-12-RACE | Tampering | WindowsThemeProvider.CurrentTheme cross-thread read/write | mitigate | WR-02: lock-guard the read-compare-write and the getter under `_themeLock`; event dispatch stays outside the lock to avoid holding it across subscriber callbacks. |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages (12-RESEARCH.md Package Legitimacy Audit — all APIs are BCL / already-referenced shared framework). |
