Constructor reads `CurrentTheme = ReadThemeFromRegistry()` then subscribes `Microsoft.Win32.SystemEvents.UserPreferenceChanged += OnUserPreferenceChanged`. `ReadThemeFromRegistry()` opens the key via `Registry.CurrentUser.OpenSubKey(KeyPath)`, reads the value, returns `AppTheme.Dark` when the value is int `0` (`raw is int i && i == 0`) else `AppTheme.Light`, and is wrapped in try/catch returning `AppTheme.Light` on any failure (matches this codebase's "never throw from a Load-time read" convention). `OnUserPreferenceChanged` re-reads the registry, and ONLY if the resolved theme differs from the stored `CurrentTheme` updates it and raises `ThemeChanged?.Invoke(this, EventArgs.Empty)` — this diff-and-dedupe is required because `UserPreferenceChanged` fires for many unrelated preference categories (A1). Add a `Log()` Trace helper mirroring `WindowsAutostartConfigurator`'s, logging the theme resolved at construction and every actual old→new flip. `Dispose()` unsubscribes `SystemEvents.UserPreferenceChanged`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Windows registry → app | `AppsUseLightTheme` value is attacker/corruption-influenceable data crossing into the process |
| OS event thread → app | `SystemEvents.UserPreferenceChanged` invokes app code, possibly off the UI thread |
| Managed → native (dwmapi.dll) | `DwmSetWindowAttribute` marshals a `ref int` + size across the P/Invoke boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | WindowsThemeProvider.ReadThemeFromRegistry | mitigate | Read via `raw is int i` pattern-match (non-int/absent value cannot cast-crash); whole read wrapped in try/catch defaulting to `AppTheme.Light`. |
| T-12-02 | Denial of Service | WindowsThemeProvider.OnUserPreferenceChanged | mitigate | Diff-and-dedupe: `ThemeChanged` only fires on a real Light↔Dark change, preventing event storms from unrelated preference categories; cross-thread safety delegated to subscribers (documented in class XML-doc, enforced in plans 02/03). |
| T-12-03 | Tampering | NativeMethods.DwmSetWindowAttribute / DwmTitleBar | mitigate | P/Invoke declared to return HRESULT `int`; unsupported-OS failure is a silently-ignored non-zero return, never an exception (D-07). Fixed `sizeof(int)` buffer size — no caller-controlled length. asInvoker integrity only; no elevation added. |
| T-12-04 | Information Disclosure / Elevation | NativeMethods visibility | mitigate | New DWM import stays `internal`; exposed only through `public DwmTitleBar` façade. No new `InternalsVisibleTo` grant to RigToggle.App (preserves the established encapsulation boundary flagged in security_context). |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase (12-RESEARCH.md Package Legitimacy Audit) — nothing to install, no supply-chain surface introduced. |
</threat_model>
