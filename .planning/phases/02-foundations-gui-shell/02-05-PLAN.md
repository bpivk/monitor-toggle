<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Disk (state.json presence) → startup mode | The app trusts snapshot-file presence to decide Rig vs Normal on launch |
| Composition root → adapters | The one place native adapters are instantiated; forms receive only interfaces |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-MODESPOOF | Spoofing (mode state) | Startup mode derivation from state.json | accept (single-user local) | Mode is intentionally derived from snapshot presence (D-14) so a crash-in-Rig-mode is recoverable; a manually-created/deleted state.json only mis-signals mode to the sole local user — no privilege boundary, acceptable at ASVS L1 |
| T-02-ELEV | Elevation of Privilege | App manifest | mitigate | No elevation manifest added; asInvoker preserved so Phase 3's cross-process SetForegroundWindow is not broken by UIPI (Pitfall 6) |
| T-02-FAKEFAIL | Info disclosure / silent failure | Toggle exception handling | mitigate (basic) | Fake-adapter exceptions surface a clear failure message box; full per-step CORE-04 reporting deferred to Phase 5 by design |
</threat_model>
