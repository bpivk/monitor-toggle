<objective>
Give the Settings UI genuine "unset" affordances so the optional targets Plan 02 already honors at runtime can actually be left unset by the user: an explicit Clear button for the companion-app path (D-01), and a "(None — don't switch audio)" entry in each audio dropdown (D-02). Relax the Save gate to require only a valid monitor grid (D-06), while a configured-but-broken audio device or app path still blocks Save ("broken != unset"). Fix MainForm's stale "finish configuring Settings" message to reference the monitor set only (D-05/Pitfall 4).

Purpose: Without these affordances a `ReadOnly` textbox and a `SelectedIndex = -1` combo make it impossible to save an unset target — the exact bug this phase exists to remove. This plan is UI-only and shares no files with Plan 01/02, so it runs in parallel.

Output: New Clear button, sentinel dropdown entry, `_pendingAppPath` field replacing the placeholder-text-as-value pattern, relaxed validation, and the reworded MainForm message.
</objective>
