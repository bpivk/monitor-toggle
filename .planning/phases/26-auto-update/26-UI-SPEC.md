# Phase 26 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** Rig Toggle is a Windows Forms (.NET 10) desktop app, not a web app. This
> contract uses WinForms vocabulary (`Form`, `Control`, `ToolStripMenuItem`, `NotifyIcon` balloon
> tips) throughout; the template's web/CSS-oriented field names (e.g. "px", "hex") are mapped to
> their WinForms equivalents (points, `Color.FromArgb`/`SystemColors`) rather than left literal.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn/registry tooling is not applicable to a WinForms desktop app; the shadcn initialization gate was skipped for this reason, not asked |
| Preset | not applicable |
| Component library | WinForms native controls only (`System.Windows.Forms`), no third-party UI package — matches every existing Form in this codebase (`MonitorConfirmDialog`, `SettingsForm`, `MainForm`). New for this phase: a read-only `RichTextBox` used as the release-notes viewer (see Component Specification) — chosen specifically because `RichTextBox` natively supports per-run `SelectionFont`/`SelectionBullet`, which is exactly the "headers, bullets, bold" subset D-01 requires, with zero external Markdown library |
| Icon library | none — this phase introduces no new icons; `notifyIcon`'s existing tray glyph and `ToolTipIcon.Info`/`ToolTipIcon.Warning` (both already in use, see Copywriting Contract) are all that's needed |
| Font | Inherited system default (Segoe UI, resolved via `AutoScaleMode.Font` / `AutoScaleDimensions(7F, 15F)` ≈ Segoe UI 9pt at 100% DPI) — no custom `Font` family is set anywhere in the existing App layer's Designer files (confirmed via search); this phase does not introduce one either, except the one deliberate weight/size deviation documented in Typography below |

## Component Specification

New WinForms surfaces this phase adds, with concrete layout — prescriptive, not exploratory.

### 1. `UpdatePromptDialog` (new `Form`, App layer)

Structural precedent: **`MonitorConfirmDialog`** exactly (D-04) — themed `Form` constructed with `themeProvider`, `AcceptButton`/`CancelButton` wired, `ThemeApplier.ThemeButton` applied to every button at construction and on live `ThemeChanged`, `DwmTitleBar.ApplyRoundedCornersAndMica` applied post-`InitializeComponent`. Never a bare `MessageBox.Show`.

| Property | Value |
|----------|-------|
| `FormBorderStyle` | `FixedDialog` (matches `MonitorConfirmDialog`/`SettingsForm` — no resizable update dialog) |
| `MaximizeBox` / `MinimizeBox` | both `false` |
| `ShowInTaskbar` | `false` |
| `StartPosition` | `CenterParent` |
| `ClientSize` | `440 × 460` (wider/taller than `MonitorConfirmDialog`'s 384×168 to fit release notes; still a small fixed dialog, not a resizable window) |
| `AcceptButton` | `btnUpdateNow` |
| `CancelButton` | `btnLater` (Esc/close = "ask me again next launch," never silently equivalent to "Skip") |

Control layout, top to bottom, 12px outer margin (matches existing `MonitorConfirmDialog`/`SettingsForm` outer-margin convention — see Spacing Scale exception):

1. `lblHeadline` — `Location(12,12)`, `Size(416,24)`, Heading typography role (12pt Bold). Text: `"Rig Toggle v{NewVersion} is available"` (populated at runtime from `ReleaseInfo.TagName`).
2. `rtbReleaseNotes` — `Location(12,44)`, `Size(416,280)`, `ReadOnly=true`, `WordWrap=true`, `ScrollBars=Vertical`, `BorderStyle=FixedSingle`. Populated by the hand-rolled Markdown-lite formatter (D-01) using `SelectionFont`/`SelectionBullet` runs: `#`/`##` headers → Heading/Label-weight bold run; `- `/`* ` bullet lines → `SelectionBullet=true`; `**bold**` spans → bold run; anything else → plain Body-weight text. **Requires a new `ThemeApplier.ThemeRichTextBox(RichTextBox, bool dark)` method**, following the exact same pattern as `ThemeApplier.ThemeComboBox`/`ThemeMonitorGrid` (WinForms `RichTextBox` is not reached by `Application.SetColorMode` either — same category of gap this codebase has already fixed three times).
3. Empty-notes fallback: if `ReleaseInfo`'s release body is null/whitespace, `rtbReleaseNotes` is populated with the plain-text fallback copy instead of being left blank (see Copywriting Contract "Empty state").
4. 24px vertical gap (lg token).
5. Button row, `Location.Y = 424`, height 32, right-to-left priority ordering (mirrors `SettingsForm.flpButtons`' Discard-then-Save precedent, but here 3 buttons):
   - `btnSkip` ("Skip this version") — left-anchored, `Location(12,424)`, `MinimumSize(130,32)`, `AutoSize=true`/`GrowAndShrink`, lowest visual priority.
   - `btnLater` ("Later") — center, `MinimumSize(90,32)`, `AutoSize=true`.
   - `btnUpdateNow` ("Update Now") — right-anchored, `MinimumSize(110,32)`, `AutoSize=true`, is `AcceptButton` (gets the native default-button ring per `ThemeApplier.ThemeButton`'s documented `isFormDefaultButton` suppression — do not add a duplicate manual border).
   - All three buttons: `FlatStyle.Flat` via `ThemeApplier.ThemeButton` — **no new "tertiary/link" visual style is invented for Skip.** Per this codebase's established discipline (accent color and destructive-red are both reserved lists, never expanded ad hoc), Skip/Later/Update Now all share the identical neutral gray `ThemeButton` palette; they are differentiated by label text and `AcceptButton` status only, not by color.

### 2. Tray context menu — new `trayCheckUpdatesMenuItem`

Inserted into the existing `trayContextMenu.Items` (`MainForm.Designer.cs`), which is currently `[trayToggleMenuItem, traySettingsMenuItem, traySeparator, trayExitMenuItem]` (TRAY-03 locked order).

**New order:** `trayToggleMenuItem → traySettingsMenuItem → trayCheckUpdatesMenuItem → traySeparator → trayExitMenuItem`.

Rationale: matches the menu's existing descending-frequency convention (toggle = daily use, Settings = occasional, Check for Updates = rare) — the new item slots directly above the separator/Exit, not between Toggle and Settings. Text: `"Check for Updates"`. `ToolStripMenuItem`, same construction pattern as `traySettingsMenuItem` (no icon, no submenu).

### 3. `SettingsForm` — new "Check for Updates" button

Placed as a standalone button, **not** inside `flpButtons` (which stays exactly Discard Changes / Save Settings, right-aligned, per existing 22-UI-SPEC layout). New button is left-anchored on the same button row/area, mirroring the common "secondary action bottom-left, primary actions bottom-right" convention:

| Property | Value |
|----------|-------|
| Name | `btnCheckForUpdates` |
| Text | `"Check for Updates"` |
| `AutoSize` | `true`, `AutoSizeMode.GrowAndShrink` |
| `MinimumSize` | `(140, 32)` — wider than `btnBrowse`'s (70,25) since the label is longer, matching `btnSaveSettings`'s 32px height for row alignment |
| `Anchor` | `Bottom, Left` |
| Styling | `FlatStyle.Flat` via `ThemeApplier.ThemeButton` — identical neutral palette, no special emphasis |

### 4. Toasts (all via existing `notifyIcon.ShowBalloonTip`, never `MessageBox`)

Every new toast in this phase reuses the **exact existing call shape** — `ShowBalloonTip(3000, title, ToggleResultFormatter.TruncateForBalloon(body), icon)` — and inherits the same accepted tradeoff already documented on `ApplyTrayVisibility()`: **if the user has both tray-visibility preferences off, `notifyIcon.Visible` is false and the balloon silently renders nothing.** This is not a new edge case introduced by this phase — it's the same accepted behavior every existing toggle/hotkey toast already has, and this phase must not special-case around it (e.g. by forcing `notifyIcon.Visible = true` just to show an update toast).

`ToolTipIcon` usage is constrained to the two values already used anywhere in this codebase — **`Info` and `Warning` only, never `Error`** (grep-confirmed: no existing call site uses `ToolTipIcon.Error`):

| Toast | Icon | Notes |
|-------|------|-------|
| "Updating…" (indeterminate, between confirm and relaunch) | `Info` | See D-03; no progress bar. Fires once, does not need to persist since the process restarts shortly after. |
| Manual check, already up to date (D-06) | `Info` | |
| Manual check, check itself failed (D-07) | `Warning` | Must read as visibly different from the up-to-date toast, per D-07 |
| Download/apply failed after confirm (D-08, includes D-11 checksum mismatch) | `Warning` | |
| Auto-rollback on next launch after failed first start (D-09) | `Warning` | |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Bullet-indent-to-text gap inside `rtbReleaseNotes`' rendered markdown runs |
| sm | 8px | Gap between `lblHeadline` and `rtbReleaseNotes`; gap between the three buttons in `UpdatePromptDialog`'s button row |
| md | 16px | Not directly used as a literal control gap this phase — reserved token, see Exceptions for the actual 12px outer-margin value in use |
| lg | 24px | Vertical gap between `rtbReleaseNotes` and the button row |
| xl | 32px | Not used this phase (dialog is small; no layout gap this large is needed) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- **12px outer form margin** on `UpdatePromptDialog` (not a multiple of 8) — deliberately matches the pre-existing `MonitorConfirmDialog`/`SettingsForm` outer-margin convention rather than deviating to a strict 8pt scale, for visual consistency across all dialogs in the app.
- **Button `MinimumSize` values** (e.g. 90×32, 110×32, 130×32, 140×32) follow existing per-button sizing precedent (`btnBrowse` 70×25, `btnSaveSettings`/`btnDiscardChanges` 110×32) rather than the spacing-scale tokens above — WinForms button sizing in this codebase is governed by `AutoSize`+`MinimumSize`, not padding tokens, and this phase does not change that convention.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 9pt (Segoe UI, inherited `DefaultFont`) | Regular (400) | N/A — WinForms has no explicit line-height property; multi-line text areas (`rtbReleaseNotes` plain-text runs, toast bodies) rely on font-metric auto line spacing, same as every existing multi-line `Label` in this codebase (e.g. `lblMessage`, `lblMonitorExplain`) |
| Label | 9pt (Segoe UI) | Bold (700) | N/A, same as Body — used for markdown `##`/`###`-level headers and inline `**bold**` spans inside `rtbReleaseNotes`, and for the "Check for Updates" button text (button text itself stays Regular; only the RichTextBox emphasis runs use this role) |
| Heading | 12pt (Segoe UI) | Bold (700) | N/A, single-line — `lblHeadline`'s "Rig Toggle vX.Y.Z is available" text and any markdown `#`-level (top) header inside `rtbReleaseNotes` |
| Display | N/A | N/A | N/A | This phase introduces no display-scale text (no splash/hero text); if ever needed, reuse the Heading token rather than adding a fourth size |

Exactly 3 sizes in use (9pt, 9pt, 12pt) and exactly 2 weights (Regular, Bold) — matches the template's "3-4 sizes, 2 weights max" ceiling and this codebase's existing near-total absence of custom Font usage (only prior exception in the whole App layer: `MonitorIdentifyOverlay`'s 120pt digit display, unrelated to this phase).

## Color

All values given as dark-mode / light-mode `Color.FromArgb(...)` / `SystemColors.*` pairs, reusing `ThemeApplier`'s existing literal palette verbatim — **no new color literals are introduced by this phase.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark: `Color.FromArgb(32,32,32)` / Light: `SystemColors.Control` | `UpdatePromptDialog`'s form surface (via `ThemeApplier.ThemeFormSurface`, same as `MainForm`) |
| Secondary (30%) | Dark: `Color.FromArgb(45,45,48)` / Light: `SystemColors.Window` | `rtbReleaseNotes` background (new `ThemeApplier.ThemeRichTextBox` method, same literal pair as `ThemeComboBox`/`ThemeMonitorGrid`'s cell background) |
| Accent (10%) | **Not introduced this phase.** | Existing accent tokens (`IThemeProvider.AccentColor` on the dashboard toggle-switch ON-fill, tile ON-icon, and focus rings) are unchanged and untouched by this phase. `UpdatePromptDialog`'s buttons, headline, and notes text all use the existing neutral `ThemeButton`/text-color palette — this phase deliberately does not expand the accent-reserved list. |
| Destructive | **Not applicable.** | No destructive/red action exists in this phase. "Skip this version" is a reversible preference (a future newer version still re-prompts, per D-02) and uses the identical neutral `ThemeButton` gray palette as every other button here — it is explicitly NOT styled as a warning/destructive action. |

Accent reserved for: dashboard toggle-switch ON-state track fill, monitor-tile ON-state icon fill, and both controls' keyboard-focus rings — **unchanged list, this phase adds nothing to it.**

Text colors (same literals as `ThemeButton`/`ThemeComboBox`): Dark `Color.FromArgb(240,240,240)` / Light `SystemColors.ControlText` for `lblHeadline` and Body/Label text inside `rtbReleaseNotes`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Update Now"** — `UpdatePromptDialog`'s `AcceptButton`; confirms download+apply, per D-02/UPDATE-03 (nothing downloads before this click) |
| Empty state heading | *(no list/collection UI this phase — see "Empty state body" for the one genuine empty-content case: a release with no notes)* |
| Empty state body | `"This release doesn't include notes. See the full release on GitHub for details."` — shown inside `rtbReleaseNotes` in place of parsed markdown when `ReleaseInfo`'s body is null/whitespace |
| Error state | Manual check failure (D-07): title `"Rig Toggle"`, body `"Couldn't check for updates — {reason}. Try again from the tray menu or Settings."` (Warning icon). Download/apply failure (D-08/D-11): title `"Rig Toggle"`, body `"Update to v{NewVersion} failed to install ({reason}) — you're still running v{CurrentVersion}."` (Warning icon). Both truncated via `ToggleResultFormatter.TruncateForBalloon` before display, matching the existing 250-char balloon-safe convention. |
| Destructive confirmation | **Not applicable** — no destructive action this phase (see Color table's Destructive row for the explicit reasoning) |

Additional copy this phase introduces (not covered by the template's fixed rows, listed here since Copywriting is a checker dimension):

| Element | Copy |
|---------|------|
| Dialog headline | `"Rig Toggle v{NewVersion} is available"` |
| "Later" button | `"Later"` — closes the dialog, re-prompts next launch (and remains reachable via manual check any time), per D-02 |
| "Skip this version" button | `"Skip this version"` — persists a suppressed-version marker; that specific version won't re-prompt until a newer one ships, per D-02 |
| "Updating…" toast | title `"Rig Toggle"`, body `"Downloading and installing update…"` (Info icon), per D-03 |
| Already-up-to-date toast (manual check) | title `"Rig Toggle"`, body `"You're already on the latest version (v{CurrentVersion})."` (Info icon), per D-06 |
| Auto-rollback toast (next launch after failed first start) | title `"Rig Toggle"`, body `"Update to v{NewVersion} failed to start — reverted to v{CurrentVersion}."` (Warning icon), per D-09 |
| Tray menu item | `"Check for Updates"` |
| Settings button | `"Check for Updates"` |

All toast bodies follow the existing `title="Rig Toggle"` convention already used for warning-path toasts in `MainForm.cs` (not the dynamic `ToggleResultFormatter.FormatModeTitle` title, which is specific to toggle-result toasts) and are passed through `TruncateForBalloon` before display.

## UI Considerations

> Populated by the ui-phase UI-consideration probe. Shape-rooted UI *state* coverage
> (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy.

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | `rtbReleaseNotes` body (`UpdatePromptDialog`) | ✅ covered | A null/whitespace GitHub release body renders the "Empty state body" fallback copy above instead of a blank control |
| loading | Confirm-to-relaunch interval | ✅ covered | Indeterminate "Updating…" toast (Info icon) per D-03 — no percentage/progress bar, no in-dialog progress control |
| error | Manual "Check for Updates" failure | ✅ covered | Distinct Warning-icon toast copy, explicitly different from the up-to-date toast per D-07 |
| error | Automatic on-launch check failure | ✅ covered | Silent no-op — no toast, no dialog, matching the best-effort/never-block-startup posture already established for `RegisterHotkeyAtStartup` and `EnableDebugLogging` |
| error | Download/apply failure (interrupted, disk-full, locked file, checksum mismatch) | ✅ covered | Warning-icon toast, app keeps running the old version, per D-08/D-11 |
| partial | New exe crashes on its first startup after the swap | ✅ covered | Next launch auto-rolls back to the retained `.old` exe and shows the auto-rollback Warning toast, per D-09's confirmed-healthy marker |
| populated | Release available, notes present | ✅ covered | `UpdatePromptDialog` shows headline + lightly-formatted release notes + three buttons |
| long-text | `rtbReleaseNotes` body | ✅ covered | `ScrollBars=Vertical` inside a fixed, non-growing `ClientSize(440,460)` dialog — arbitrarily long notes scroll, they never expand the dialog frame |
| overflow | Markdown constructs beyond the supported subset (tables, images, nested lists, links) | 🧪 backstop | Unsupported constructs are expected to degrade to plain unformatted text rather than break the hand-rolled formatter, but this has not been verified against a real GitHub release body containing rich formatting — verify with an actual/synthetic oversized release note during implementation or rig verification |
| zero-one-many | Latest-release check result | ✅ covered | GitHub `/releases/latest` returns exactly one release or 404 — `UpdateOrchestrator` has exactly two branches (newer found / not found-or-unreachable), no list/collection UI is needed this phase |
