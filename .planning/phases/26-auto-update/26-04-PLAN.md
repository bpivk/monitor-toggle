<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network → UI | The GitHub release body is attacker-influenceable text (anyone with write access to the repo's releases) rendered into a control in this app's own process. |
| user preference → update path | The persisted skip decision suppresses future prompts and therefore future fixes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-12 | Tampering | release-body text rendered into `rtbReleaseNotes` | medium | mitigate | The renderer only ever assigns plain text through `SelectionFont`/`SelectionBullet` runs and never assigns `Rtf` or any control property that would interpret markup, so a body containing RTF control words or markup is displayed literally rather than executed as formatting. The control is `ReadOnly` and no link-clicking is enabled. |
| T-26-13 | Denial of Service | a pathological release body stalls or crashes the parser | low | mitigate | The formatter is a single linear pass with no backtracking regex, and the whole body is wrapped in a catch that degrades to a raw plain-text dump. Covered by the arbitrarily-long-body and unmatched-delimiter test cases. |
| T-26-14 | Repudiation | a skip silently suppresses every future update | medium | mitigate | The skip stores one version tag and the automatic path compares numerically, so a strictly-newer release still prompts. The value lives in the hand-editable `settings.json` the developer already reads, so the suppression is inspectable and reversible. Enforced by the prohibition and its two paired tests. |
| T-26-SC | Tampering | supply chain | high | mitigate | Zero package-manager installs — D-01 explicitly calls for a hand-rolled formatter rather than a Markdown library, so no package-legitimacy checkpoint applies. Asserted by the csproj-diff acceptance criterion. |
</threat_model>
