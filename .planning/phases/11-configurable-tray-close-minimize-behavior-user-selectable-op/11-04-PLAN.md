  <what-built>
    Phase 11 makes the window Close (X) and Minimize behaviors settings-driven and derives the tray icon's existence from them:
    - Two new Settings checkboxes: "Closing the window (X) minimizes to tray" and "Minimizing the window also sends it to tray", grouped directly above "Start with Windows".
    - Close (X) hides to tray only when the first box is checked (default OFF = X exits the app).
    - Minimize hides to tray only when the second box is checked (default OFF = standard OS minimize).
    - The tray icon is shown only when at least one of the two boxes is checked, applied live on Save and at startup.
  </what-built>
  <action>
    This is a human-verification checkpoint — the executor does not modify code. Build and launch the app on Windows and walk the human through the five verification steps in `<how-to-verify>`, recording pass/fail for each. Any deviation is captured verbatim as a gap for `/gsd:plan-phase --gaps`. Do not "fix" the D-10/D-11 accepted tradeoffs (silent toasts when both settings off; autostart + X-exits combining with no warning) — those are expected behaviors, not defects.
  </action>
  <how-to-verify>
    Build and run the app on Windows: `dotnet run --project src/RigToggle.App/RigToggle.App.csproj` (or launch the published exe).

    1. FRESH-UPGRADE DEFAULT (D-02): With a settings.json that has never had these fields (or after deleting %LocalAppData%\RigToggle\settings.json and reconfiguring the minimum required settings), confirm on launch there is NO tray icon, and pressing the window's X button EXITS the app (process ends) rather than hiding it. This is the intended, twice-confirmed default — verify it is actually happening.
    2. CLOSE-TO-TRAY ON: Open Settings, check "Closing the window (X) minimizes to tray", click Save. Confirm the tray icon APPEARS immediately (no app restart). Press X — the window hides to tray (does not exit). Left-click the tray icon — the window restores and focuses.
    3. MINIMIZE-TO-TRAY ON: Open Settings, check "Minimizing the window also sends it to tray", click Save. Press the minimize button — the window disappears from the taskbar entirely and is reachable only via the tray icon; left-click the tray icon restores it. Then UNcheck it, Save, and confirm minimize now goes to the normal taskbar (standard OS minimize).
    4. LIVE TRAY EXISTENCE: With both boxes checked, Save, confirm tray icon present. Uncheck BOTH, Save — confirm the tray icon DISAPPEARS immediately and X once again exits the app. Re-check either one, Save — tray icon reappears immediately.
    5. TRAY MENU/ICON STILL WORK (regression): While the tray icon is shown, right-click it (context menu: Switch mode / Settings / Exit still present and functional) and confirm the icon still reflects the current mode (normal vs rig) as in Phase 8.

    Accepted, do-not-report-as-bug behaviors (per D-10/D-11): with both boxes off, toggle toasts render nothing (silent) — this is expected; and autostart + X-set-to-exit combining freely with no warning is expected.
  </how-to-verify>
  <verify>
    <human-check>All five verification steps behave exactly as described; any deviation is captured as a gap.</human-check>
  </verify>
  <acceptance_criteria>
    - Step 1: no tray icon on fresh-default launch AND X exits the app
    - Step 2: tray icon appears live on Save; X hides to tray; left-click restores
    - Step 3: minimize hides to tray (off taskbar) when on; standard OS minimize when off
    - Step 4: tray icon appears/disappears immediately on Save for every OR-combination of the two settings
    - Step 5: tray context menu and mode-reflecting icon still function when the icon is shown
  </acceptance_criteria>
