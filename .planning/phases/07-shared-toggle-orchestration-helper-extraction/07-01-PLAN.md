<objective>
Extract a single, reentrancy-safe orchestration entry point (`ToggleOrchestrator`) that wraps
the existing `ToggleService` with a non-blocking busy-guard, so any second toggle request
arriving while one is already in flight is rejected immediately rather than corrupting state.
Refactor the one existing caller (`MainForm.BtnToggle_Click`) and the composition root
(`Program.cs`) to route through the orchestrator instead of calling `ToggleService` directly.

Purpose: Closes CORE-06. Establishes the shared pipeline every future trigger (tray menu /
hotkey / CLI in Phases 8-10) will call through — this phase locks that integration contract.

Output: Two new Core types (`ToggleOrchestrator`, `ToggleInProgressException`), two new test
artifacts (a blocking test double + the orchestrator test suite), and a minimal-diff refactor
of `MainForm`/`Program.cs`. `ToggleService` itself is untouched (D-03).
</objective>

    ToggleOrchestrator behavior to encode as tests (all deterministic — no Thread.Sleep, no timing guess):
    - Idle ToggleToRigMode() delegates to ToggleService.ToggleToRigMode() and returns its ToggleResult.
    - Idle ToggleToNormalMode() delegates to ToggleService.ToggleToNormalMode() and returns its ToggleResult.
    - Reentrancy (same direction): with a BlockingMonitorController holding the first call inside the guarded region, a second ToggleToRigMode() throws ToggleInProgressException; after release, the first call still completes with a successful ToggleResult.
    - Reentrancy (cross direction, D-02): with the first ToggleToRigMode() held in the guarded region, a second ToggleToNormalMode() throws ToggleInProgressException (one shared flag guards both directions).
    - Flag release after failure (Pitfall 3): a ToggleToRigMode() with unconfigured settings throws InvalidOperationException (NOT ToggleInProgressException); a subsequent ToggleToRigMode() with configured settings then succeeds — proving the finally-block reset ran and the orchestrator is not wedged.
    - Pass-throughs: IsInRigMode() and IsSettingsConfigured() return the wrapped service's values and are safe to call while a toggle is in flight (unguarded).
    - Type contract: ToggleInProgressException is assignable to InvalidOperationException (Assert.IsAssignableFrom) — this is what makes MainForm's existing catch handle it with zero UI changes (D-05).
