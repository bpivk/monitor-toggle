<objective>
Repoint every accent-tinted element from the hardcoded placeholder to the live provider value, and make a live accent flip repaint them.

Purpose: Plan 01 built the source. This plan is the swap. Because Phase 20 deliberately funnelled all five accent consumers through one shared literal, this is a small, mechanical change — the value of the phase is in swapping exactly the right five and nothing else.
Output: `MainForm` subscribes to `AccentColorChanged` with the same handler it already uses for light/dark, its `AccentColor` property becomes a pass-through, and `ThemeApplier`'s two accent-consuming helpers take the color as a parameter instead of deriving it from `dark`. Build green, 82 tests. Behavior visibly changes for the first time in this phase.
</objective>

**The two-call-site rule (19-RESEARCH.md Pitfall 1, must survive):** `ApplyDashboardTheming()` is reached from both `OnThemeChanged` (line 167) and `InitializeTrayState()` (line 267). Wiring `AccentColorChanged` into `OnThemeChanged` inherits both paths for free — that is why no new call site is needed.

**Thread marshalling:** `OnThemeChanged` (line 151) already begins with an `InvokeRequired` check that re-dispatches via `BeginInvoke` (lines 153-156). Reusing that handler is what makes the off-thread `AccentColorChanged` safe. This is another reason not to write a separate handler.

**Subscription lifetime:** `MainForm`'s provider subscriptions are made once in the constructor and deliberately never unsubscribed on `Hide()`/`Show()`/`FormClosed` — the form is hidden-not-closed for most of its runtime under tray-resident operation. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `IThemeProvider.AccentColor` (OS-derived, user-controlled) → GDI+ paint code | The color painted into tiles, the switch track, and focus rings is now fully attacker-or-user-controllable via a current-user registry value, rather than a designer-chosen constant. Any 32-bit value is a valid color, so the risk is legibility, not memory safety. |
| `SystemEvents` callback thread → WinForms control tree | `AccentColorChanged` may be raised off the UI thread; touching a control from there is undefined behavior. |
| Accent-tinted element set (D-04) → phase scope | The five-consumer list is the scope boundary; silently widening it is scope tampering, and this plan's audit criteria are the enforcement. |
