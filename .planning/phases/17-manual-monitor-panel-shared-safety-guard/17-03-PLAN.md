<key_differences_from_settings>
The panel deliberately diverges from `OpenSettingsDialog` in four ways. Each is intentional; do not "normalize" them:

1. **Non-modal `Show()`, never `ShowDialog()`.** PANEL-03 requires live updates while the panel is open, and the panel must not block the main window or tray.
2. **Cached instance, not fresh-per-open.** `SettingsForm`/`MonitorConfirmDialog` use `using var ... ShowDialog()` because they are transient. A non-modal window must be re-focused rather than duplicated, so `MainForm` holds one `MonitorPanelForm?` field and re-creates it only when it is null or already disposed (a closed non-modal `Form` disposes itself).
3. **Does NOT unregister the global hotkey.** `OpenSettingsDialog` unregisters the hotkey for the dialog's whole lifetime (TRIG-01/D-07) because a mid-edit hotkey could race a Settings save. The panel has no such edit state, and disabling the hotkey for a potentially long-lived window would silently break the user's primary trigger. Concurrency between a hotkey toggle and a panel action is instead handled by Plan 17-01's `BeginExclusiveMonitorAccess()` lease inside the panel — do not add a hotkey unregister here.
4. **Does NOT call `RefreshUi()` on close.** `OpenSettingsDialog` does, because Settings can change what a toggle does. A panel action changes live monitor state but never the Rig/Normal mode flag, so `MainForm`'s mode indicator is unaffected.
</key_differences_from_settings>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-17-12 | Elevation of Privilege | Panel reaching capabilities beyond monitor control | mitigate | The factory injects only `monitorController`, `settingsStore`, `themeProvider`, and `toggleOrchestrator`. It deliberately does NOT inject `audioController`, `appController`, `autostartConfigurator`, `modeStore`, or `markerStore`, so the panel structurally cannot switch audio, launch processes, change autostart, or write mode state. | T-17-14 | Denial of Service | Duplicate panel windows accumulating from repeated clicks, or an orphaned disposed instance causing `ObjectDisposedException` | mitigate | Single cached `MonitorPanelForm?` field with a `null || IsDisposed` re-create guard; a second click focuses the existing window. |

| T-17-16 | Spoofing | Tray menu item impersonating a different action | accept | Locked copy from 17-UI-SPEC.md (`Monitors`), single-user local app, no remote surface. |
