<objective>
Fix `WindowsMonitorController.GetAllMonitors()` — rig testing at the Phase 6 checkpoint (06-06, NO-GO) found it returns duplicate rows per physical monitor (one per stale/inactive CCD path from `PathInfo.GetAllPaths()`, not deduplicated by the stable `DevicePath`) and can report `IsPrimary=true` for more than one monitor at once (it reads `IsGDIPrimary` off potentially-stale inactive `PathInfo` entries — the same "inactive-path fields are unreliable" landmine already worked around elsewhere in this file, e.g. `Restore()`).

The fix: (1) deduplicate the result by `DevicePath` — exactly one `MonitorInfo` per physical monitor; (2) source `IsPrimary`/`IsActive` only from `GetActiveMonitors()` (already correct, `GetActivePaths()`-based) for currently-active monitors, and hard-code `IsPrimary: false` / `IsActive: false` for monitors not currently active (a disabled monitor cannot be primary). Extract a pure `MergeAllMonitors()` seam so the dedup/primary logic is unit-testable without live CCD hardware.

Purpose: Unblock the 06-06 rig checkpoint (DISPLAY-04/DISPLAY-05 remain open on the NO-GO) so the Settings grid lists each physical monitor exactly once with a correct single primary.
Output: Corrected `GetAllMonitors()`, a tested pure `MergeAllMonitors()` helper, and regression tests.
</objective>
